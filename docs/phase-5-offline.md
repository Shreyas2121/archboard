## Run and recovery

Use Node.js 22.23.2 and pnpm 11.24.0. Supply the ignored root `.env` and `.env.local` as described in [README](../README.md). The API needs paired pooled and direct PostgreSQL URLs for the same database and role. Confirm the intended database before applying the pending migration. Do not print credentials or put private board content in evidence.

`pnpm phase5:verify --non-browser` runs the frozen install, formatting, lint, types, focused Node state tests, workspace build, generated bundle/cache-policy scans, API unit and real PostgreSQL integration suites, auth schema, configured migration state, dependency boundaries, and API secret scan. It returns nonzero when a check fails. Because it includes database children, this command is now **UNRUN (deferred by user — until Version 1 implementation is complete)**; do not use it as an implementation shortcut. Run its database-free checks individually instead. Database-backed HTTP/auth/session/socket suites and migration/schema inspections share that deferral. `pnpm phase5:verify`, `pnpm phase4:verify`, `pnpm test`, `pnpm test:browser`, native sync-client browser tests, and all served preview scripts remain **UNRUN (deferred by user)** under the independent browser pause. The full Phase 5 command will also fail explicitly until combined A07/A10/A22/A24 served harnesses are wired.

Offline data is a local copy, not a backup. A cached owner/editor can edit only a previously opened active board while holding its namespace Web Lock. “Saved on this device · offline” means the update and outbox entry committed locally; only a durable server ACK permits “Saved to server.” On access, session, schema, or storage failure, keep the exact account/board namespace and use **Download recovery** before an explicit reset. Offline sign-out stops local authenticated editing while server invalidation is pending. A later online session must resolve that pending intent before upload or authenticated reuse.
