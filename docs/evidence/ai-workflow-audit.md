## Causes and changes

1. **Serial accounting queries dominated admission and settlement.** Preparing approximately 16 ledger rows used an insert and locked read for every row, followed by individual balance writes, under the namespace accounting lock. The transaction-local cache helped repeated reads but did not remove the initial round trips. Preparation now batches materialization and locked reads by table and global/actor scope, and stages balance updates for two table-level flushes. Global-before-actor ordering and transaction-scoped locks remain. Allocations, reservations, attempt records, immutable settlements and deferred constraints remain intact. Optional-content savepoints flush prior accounting first; rollback clears both cached and staged balances. A flush failure aborts the transaction.
2. **Creation competed with its own worker.** After durable admission started a worker, the route reread the run through another locked transaction before replying. Pending admission now returns its authorized, content-free acknowledgment directly. Terminal/cache/replay content still requires a current authorized read.
3. **Status competed for accounting locks.** Omitting ledger preparation had left global, actor, fingerprint and run coordination on readonly status requests. Reads now check actor ownership and hold current board authority through disclosure without acquiring AI accounting locks. Request-frequency accounting uses its own actor request lock; admission/dispatch/settlement still use the accounting coordinator. Board permission fencing remains, so a read can still wait behind a board operation.
4. **Slow active reads were treated as idle subscriptions.** The 30-second idle timer could expire during session checks, frequency admission or a status query. Active work now clears the idle timer before those checks; idle time resumes after delivery. Stream lifetime, connection limits, current cookie checks and board reauthorization remain bounded. Unit coverage verifies a slow preflight and session expiry with no second private read.
5. **Connection failure did not recover coherently.** The client fetched status for every SSE snapshot, and event closure/errors left manual-only recovery. Pending snapshots now update status directly; terminal events fetch private results once. Reconnect and bounded GET fallback always use the original run ID. Superseded requests are aborted and late responses ignored. Coming online resumes known pending runs; uncertain creation still requires explicit recovery with the identical body and key.
6. **Preview reloaded the development page.** The baseline Vite log showed late discovery of `elkjs/lib/elk.bundled.js` at Preview, followed by a page reload that discarded private session state. The layout dependency is now prebundled at startup. A separate actual-worker probe then exposed `_Worker is not a constructor`: ELK's bundled shim detects a module-worker environment and installs its native entry instead of exporting the fake worker used by its wrapper. Layout now uses ELK's native worker API and an emitted worker URL, with explicit normal-completion cleanup and the existing termination/deadline/fallback behavior. Final browser previews report **Layered layout**. Both owner and engine assets are bounded, isolated from the main bundle and precached. See [ELK's official worker documentation](https://github.com/kieler/elkjs#usage) and [Vite dependency optimization](https://vite.dev/config/dep-optimization-options#optimizedeps-include).
7. **Worker failures were swallowed.** The background catch now records safe stage/code diagnostics and failure counters. Ambiguous settlement commits retry the identical immutable settlement, without another provider execution. Result-encryption rejection produces a terminal content failure while retaining known usage charges. Authoritative usage on a provider's terminal failure remains known; uncertain transport execution still retains unknown liability. Persistent database failure cannot safely manufacture a terminal write: the durable run remains available for existing expiry/recovery.
8. **The inspector was congested.** AI now opens from the labeled toolbar button into a wide, accessible dialog. Workflow ownership and private guidance drafts live above its portal, so closing it preserves the original request while the board is open. Board/account changes clear them. Editor shortcuts and playback treat the dialog as modal, and closing returns focus to the toolbar. Generation distinguishes authentication, admission, queued execution, generation and terminal results. Failures use readable explanations. A visible run ID and an explicit original-ID lookup support full page reload recovery without persisting prompts or automatically generating again.

Recovery proof:

- Dropped-SSE case: closed/reopened the dialog while pending, retained the same ID, three bounded event attempts, then an authorized original-ID GET, layered preview, Apply and reload. **One** creation POST.
- Lost-acknowledgment case: upstream creation actually returned 202; the harness withheld that response. Explicit “Recover original request” made a second POST with identical body and key and returned the **same run ID**. Normal SSE and terminal GET then reached preview/Apply. After reload, “Check original run” retrieved that same ID without another POST.
- Runtime aggregate after those two distinct final runs: **two provider calls**, two cache misses, no unknown outcomes, worker failures, provider failures or settlement failures. Two POSTs for uncertain recovery did not execute a second provider call.
- The final applied board loaded in a fresh authenticated browser context without its previous IndexedDB/local board cache: **three nodes, zero creation POSTs**.
