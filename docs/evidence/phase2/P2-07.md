## Behavior proved

- The palette creates component, code, schema, and note cards at the visible viewport center. Each
  creation uses `crypto.randomUUID()`, the active 16-unit grid, a bounded cascade offset, and the
  contract sizes 240 × 140, 360 × 240, 360 × 240, and 240 × 180 respectively.
- Four distinct renderers display only the fields valid for their kind. Every card keeps the fixed
  top/right/bottom/left source and target handles inert until P2-08. Persisted color tokens map to
  paired light/dark graph theme tokens rather than stored CSS values.
- A single selected card opens an inspector containing common title/color fields plus only its valid
  kind fields. Category, language, color, and external URL candidates are validated as complete
  nodes before the guarded document-model command runs.
- Title, component description/technology, and code/schema/note bodies use the reusable product
  incremental-text control. Its target accepts node, edge, boundary, and presentation text targets,
  so later edge labels/protocol and boundary titles use the same path without exposing Y.Text.
- Text input computes one minimal UTF-16 delete/insert range, calls `editGraphText`, patches remote
  values with selection mapping, buffers composition input until `compositionend`, and closes the
  local undo capture at blur/commit boundaries. Keyboard events stop at the form control.
- Oversized or otherwise invalid text remains only in the DOM draft and reports the exact remaining
  count/error. Escape restores the committed value. Single-line Enter finishes the field;
  Ctrl/Command+Enter finishes a multiline field.
- Shiki tokenizes code locally and React renders token content as text spans. Schema and note bodies
  also use React text nodes. No raw HTML, evaluator, preview iframe, external preview request, or
  remote syntax service is present.
- Component links render only after the shared schema accepts an HTTP(S) URL. They use a new tab with
  `noopener noreferrer`; invalid schemes remain inspector drafts and never reach the card.

## Contracts and ownership

- Defaults, enums, limits, graph-node validation, UUID validation, coordinate limits, and all durable
  field types come from `@archboard/contracts`. Card construction parses the complete candidate with
  `graphNodeSchema`.
- `EditorSession` exposes guarded high-level card/text/atomic-field methods. Components do not receive
  Y.Doc, Y.Map, or writable Y.Text. All writes still flow through `BrowserWriterSession.executeMutation`
  and document-model commands.
- `stopLocalUndoCapture` is now exported from the document-model public undo surface. The underlying
  implementation and origin policy are unchanged.
- Select and Textarea are checked-in shadcn source generated with the repository-recorded exact CLI
  `shadcn@4.21.0`; generated `cn` imports were aligned with the existing `@/lib/utils` convention.

## Browser evidence

A temporary Playwright observer drove installed Google Chrome against a served production build and
was removed after the run. The run used a fresh isolated browser context and the real Web Lock,
IndexedDB persistence, React Flow canvas, and production event handlers.

- Created all four card kinds from the palette and observed one renderer for each kind. The inspector
  edited and committed every representative field, including component category/description/
  technology/link, code language/body, schema body, note body, common title, and color controls.
- Inserted a character in the middle of `ABCDE`, retained the caret as `ABXCDE`, deleted it back to
  `ABCDE`, and then continued editing. A Japanese composition sequence committed once at
  `compositionend` and hydrated as `Line one\n入力`.
- Entered 20,001 characters into a body. The UI reported the one-character overage, Escape restored
  the prior body, and reload hydrated the prior committed content rather than the rejected draft.
- Rendered `<script>window.__archboardExecuted = true</script>` in a JavaScript code card. The global
  marker remained unset, the source remained visible as text, and the JavaScript body hydrated after
  reload.
- Rejected `javascript:alert(1)` with an HTTP(S)-only error and rendered no unsafe link. Committed
  `https://example.com/docs`, verified `rel="noopener noreferrer"`, and observed zero requests to
  that origin, proving no preview fetch.
- Reloaded the production page and recovered all four card kinds and their edited fields from
  IndexedDB.
