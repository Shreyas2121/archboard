## Behavior proved

- Opening a fresh namespace durably records a sequence-zero Yjs baseline before enabling edits.
  Reopening applies the newest exact-namespace snapshot and only later contiguous local-log records,
  validates and projects a candidate document, checkpoints the validated session state, and only
  then attaches the local-write observer.
- A real-browser create-two-nodes/connect/close/reopen path preserves graph IDs, content, geometry,
  handles, and edge endpoints. Hydration emits no new local log or outbox record.
- Immutable external-store snapshots expose `loading`, `ready`, `saving`, `saved`, `storage-error`,
  and `recovery-required`, including exact pending-write counts, editability, diagnostic, and error
  code. Subscribers observe saving before saved.
- Local command bytes still enter `localUpdates` and `outbox` atomically. Failed transaction bytes
  enter neither store, never become transport eligible, pause editing, never emit saved afterward,
  and remain available through the in-memory projection.
- Snapshot creation triggers at either 32 uncovered updates or 512 KiB of uncovered update bytes.
  The replacement snapshot commits before a separate covered-log deletion transaction. Outbox
  records are never part of local compaction.
- An injected interruption after snapshot replacement leaves the new snapshot plus old covered logs.
  A new browser session rebuilds the same projection, ignores covered records, safely removes them,
  and retains every outbox entry. A later post-snapshot log also replays correctly.
- Missing base snapshots, local-sequence gaps, invalid snapshot bytes, and unsupported cached graph
  versions remain non-editable recovery states. Cached bytes are retained without migration or
  automatic reset.
- Exact-namespace listing and transactional deletion cover all four stores. Browser tests prove
  deletion cannot affect neighboring origins, users, boards, or schema versions and that an
  unresolved board ID is rejected.
- Close is idempotent, flushes already-observed pending writes, detaches the observer, and tolerates
  concurrent partial initialization.

## Contracts used

- Storage identity remains deployment origin + reserved `local-demo` user key + application UUID
  board ID + graph schema version. No prefix, account-wide, or origin-wide deletion API exists.
- `localSnapshots` stores exact Yjs state bytes and its highest included local sequence.
  `localUpdates` remains ordered by namespace and sequence; `outbox` retains exact local bytes and
  SHA-256 payload hashes.
- Hydration uses `COMMAND_ORIGINS.HYDRATION`; its observer is not attached until validation succeeds.
  Local edit and structural origins remain the only sources of local log/outbox writes.
- `validateGraphDocument` and `projectGraphDocument` are both completed before status becomes ready.
  Current `GRAPH_SCHEMA_VERSION` remains authoritative; no DTO, schema, or database version changed.

## Browser evidence

Headless Chrome executed IndexedDB rather than an in-memory mock. The suite closes database-backed

transaction aborts, replaces snapshots, preserves outbox records, and verifies exact namespace
isolation across origin/user/board/schema dimensions.

## Failure injection

- `AFTER_LOCAL_UPDATE_WRITE` aborts the combined local-log/outbox transaction. Both stores remain
  empty for the failed bytes; status becomes storage error, editing pauses, saved is never emitted,
  and the in-memory projection remains exportable.
- `AFTER_SNAPSHOT_WRITE` stops between committed replacement and covered-log cleanup. Both replay
  paths coexist, and the next session hydrates equivalently before removing redundant covered logs.
- A missing sequence, invalid Yjs snapshot bytes, and unsupported schema namespace each enter
  recovery required without deleting or overwriting cached records.
