## Behavior proved

- The production `/demo` route completed the local A28 keyboard flow in Chrome: tab to the palette and create a component; tab to the new canvas node, select and inspect it; edit its title; apply numeric X and width; use the review-first keyboard connection dialog; delete the focused node with Delete and restore it; zoom in, fit content, and open keyboard help. A 390 × 844 view displayed the read-only explanation and no editable palette buttons.
- The help dialog trapped 30 successive Tab presses and returned focus to its named trigger after Escape. This check exposed missing focus return for externally controlled help and reset dialogs; both now explicitly return focus to their trigger buttons.
- A script-like title, clipboard note, and code-card body remained text in the rendered canvas. `javascript:` was rejected by the External URL field and yielded no unsafe anchor. A valid HTTPS link used `target="_blank"` and `rel="noopener noreferrer"`. Downloaded recovery JSON retained the test payload after parsing while its raw bytes escaped `<` as `\u003c`.
- `phase2:verify` runs and labels every static, unit, real-browser, independent build, workspace build, boundary, and bundle audit child; failures propagate. The production bundle audit inspected 127 JS/CSS/HTML assets for backend secret names, PostgreSQL URLs, and runtime CDN/registry references.
- The cached typical graph opens under 2 seconds and dragging meets the 32 ms p95 target without per-move persistence. Panning misses the 32 ms p95 target. The measurement command exits nonzero on that miss.

## Browser evidence

- Installed Chrome 153 on `/demo`, with native Web Locks, IndexedDB, and download behavior. The keyboard path used Tab, Enter, Delete, Ctrl+A, and text input; it did not use pointer activation. The new node was selected by keyboard and its inspector was available. Numeric geometry reported `Geometry updated.` and the connection dialog reported `Connection created.`. The deleted node disappeared and its same ID returned on restore. Zoom readout moved from 100% to 120%, then fit content yielded 69% in that run.
- The help dialog's focus stayed inside for 30 Tab presses and returned to the `Open keyboard help` button on Escape. Its dialog had an accessible title. The 390 px view presented the read-only notice and no palette edit controls.
- The negative probe used `<img src=x onerror="window.__archboardXss=1">` and a script tag in a code card. The sentinel was never set and no corresponding image/script element appeared in the canvas. Invalid `javascript:alert(1)` set `aria-invalid="true"` and created no link; a valid HTTPS link had `noopener noreferrer`. A parsed recovery graph contained the payload, while the raw JSON did not contain a literal `<`.

## Failure injection

- Browser security-negative payloads above were deliberately entered into local graph fields and clipboard. No code executed, and the unsafe URL did not become an anchor.
- The Phase 1 integration run inside the network sandbox did not complete reliably. Re-running the unchanged gate outside the sandbox passed all 17 PostgreSQL tests and the full remaining Phase 1 checks.

## Accessibility evidence

- Keyboard create, select/inspect, edit, numeric geometry, alternate connect, Delete/restore, fit, zoom, and help were verified in Chrome. Help dialog focus trap and return were verified; reset uses the same trigger-ref focus-return correction. Visible status text includes `Saved on this device`, and connection/geometry/delete notices have text equivalents in `role="status"` regions; the narrow-screen state explicitly says read-only.
- Actual spoken screen-reader output is **UNRUN**: headless Chrome and its accessibility tree cannot verify Narrator/NVDA announcements. A human screen-reader spot check of browser, route, controls, save/error/restore speech, and limitations is still required. This is not a WCAG audit.
