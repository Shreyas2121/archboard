## Behavior proved

- TanStack Router owns `/`, `/demo`, route-level errors, and the useful not-found screen. No
  dashboard, `/boards`, authentication, or other future route placeholder was added.
- `/demo` renders a stable workbench with top bar, collapsible palette, canvas landmark,
  collapsible inspector, and bottom controls while the local board is loading.
- Loading, seeding, writable, read-only, saving, saved, storage-error, recovery-required, and
  narrow-screen presentation are modeled as an exhaustive typed view-state record.
- Light, dark, and system preference is stored under `archboard.theme`; only the resolved theme is
  applied to the document. Theme, panels, dialog, selection references, grid snap, and minimap are
  ephemeral UI state and are not graph content.
- Narrow screens show an explicit read-only state and hide editing panels. Unimplemented graph
  actions remain disabled instead of appearing functional.

## Contracts used

- The router is the sole owner of internal navigation; shadcn `Button` uses `asChild` with TanStack
  `Link` where a navigation link needs button styling.
- Existing shadcn `Button`, `Dialog`, `Collapsible`, and `Tooltip` primitives provide interactive
  behavior. `IconButton` composes the existing button and tooltip with an accessible label.
- The Zustand store exposes narrow selectors and only accepts ephemeral selection IDs/kinds. Its
  compile-time contract rejects durable graph keys such as nodes, edges, document, projection, and
  graph.
- Tailwind utilities own component layout and styling. `styles.css` contains only global base rules
  and paired light/dark semantic tokens, including canvas dots and status colors.

## Browser evidence

A served production build was inspected in installed Google Chrome at 1440 × 900 and 390 × 844.
The final session produced no browser console errors or failed resources.

- Direct navigation and refresh at `/demo` returned HTTP 200 and rendered one `main` landmark, the
  canvas heading, `Loading local board…` status, visible Palette, and visible Inspector.
- Collapsing the Palette exposed the labeled Expand control. Cycling the theme persisted `light` to
  local storage. The keyboard-help action opened a titled/described shadcn dialog.
- `/not-a-real-route` rendered “This route is outside the boundary.” with an `Open local demo` link
  whose target was `/demo`.
- At 390 px, the shell rendered `Read-only · desktop width required`, the narrow-screen explanation,
  no visible Palette, and a compact toolbar. Desktop and narrow screenshots were visually reviewed
  and then deleted; no browser artifact or test was retained.

## Accessibility evidence

- Home, demo, error, and not-found views use semantic header/main/footer or main landmarks and a
  logical heading hierarchy.
- Every icon-only action has an accessible name in addition to its tooltip. Disabled actions state
  why they are unavailable.
- Editor status is exposed through `role="status"` and an atomic polite live region. The help dialog
  has a title, description, close control, focus trap, and Escape behavior from the shadcn primitive.
- Keyboard focus uses the shared ring token. Decorative loading animation respects reduced-motion
  preference.

## Known gaps

- This commit intentionally does not create a Y.Doc session, open IndexedDB, render React Flow,
  seed graph content, or make graph controls functional. P2-06 connects the shell to the editor
  session and projection.
- The production bundle is currently a single route chunk and crosses Vite's 500 kB advisory by
  11.26 kB before gzip. Route-level splitting is deferred until the editor feature modules exist.
