## Behavior proved

- A completed multi-node position batch and a mixed node/boundary geometry batch each emit one
  Yjs transaction and one update.
- Geometry batches validate every live target and complete candidate before mutation. Invalid
  coordinates, invalid dimensions, missing members, duplicate members, duplicate creation IDs,
  unresolved edge endpoints, and over-limit creation leave encoded document state unchanged.
- Mixed movement stores node positions and boundary rectangles as independent absolute world
  coordinates; it introduces no parent, containment, or relative-coordinate semantics.
- Duplicate/paste creation validates all nodes, edges, boundaries, IDs, references, and capacity,
  then inserts the complete batch under one structural origin.
- Batch deletion captures selected nodes/boundaries/edges plus edges internal to selected nodes,
  tombstones them in one structural transaction, and leaves external incident edges physically
  present and untombstoned. Projection hides those edges while their old endpoint is tombstoned.
- Restore retains old tombstones, assigns fresh IDs, remaps captured edge endpoints, and rejects
  unresolved node/edge references before mutation.
- Product bindings can read and subscribe to a validated graph text target without receiving a
  writable document root or `Y.Text`. Text writes remain command-only.
- Geometry/property batches use `LOCAL_EDIT`; create/delete/restore use `LOCAL_STRUCTURAL` and stay
  outside generic undo. `stopLocalUndoCapture` exposes an explicit gesture/field boundary.

## Contracts used

- Existing strict node, edge, boundary, projection, point, size, rectangle, UUID, and shared live
  entity-limit contracts are reused without DTO or limit changes.
- The Y.Doc remains the sole durable graph store. Accepted IDs remain globally non-reusable,
  edge endpoints and handles remain immutable, and physical entities/tombstones remain append-only.
- `LOCAL_EDIT` is the only origin tracked by the local undo manager. `LOCAL_STRUCTURAL`, remote, and
  hydration origins remain excluded.
- Deletion capture is session data returned to the caller; the document persists only append-only
  tombstones. Presentation-step clipboard/delete policy remains outside this command batch.

## Changed scope

- Added framework-independent batch geometry, creation, deletion/capture commands and focused

- Added a read/subscribe-only text access module and root export.
- Hardened restore preflight for globally duplicate IDs and unresolved restored references.
- Added the explicit local undo capture-boundary helper and this evidence file.
- No React, React Flow, Zustand, browser storage, clipboard, frontend tests, fixtures, DTOs, or
