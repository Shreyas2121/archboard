## Behavior proved

- Click selects one card, edge, or boundary; Shift-click toggles objects. Empty-area rectangle
  selection uses React Flow's partial-intersection mode: any positive-area overlap selects a card or
  boundary, while edge-only contact does not. Escape clears ephemeral selection.
- Selection stores only `{ id, kind }` references in Zustand. Projection changes prune missing cards,
  edges, and boundaries without a graph mutation; React Flow's selected flags are derived from that
  state.
- Card and boundary drag/resize use controlled React Flow preview nodes. Pointer-move changes remain
  local, while drag stop or resize end sends one validated `setGraphGeometry` batch using absolute
  world coordinates.
- The 16-world-unit grid remains enabled by default. React Flow snaps after viewport conversion, so
  it is zoom-independent; holding Alt switches snapping off during drag and resize. Completed values
  are clamped to shared coordinate, node-size, and rectangle limits before dispatch.
- Multi-card and mixed card/boundary movement commit one absolute geometry batch. A boundary has no
  parent/containment relationship, so moving it alone leaves visually enclosed cards unchanged.
- Left, horizontal-center, right, top, vertical-center, and bottom alignment run through a new atomic
  document-model command. Center/right/bottom calculations account for unequal node dimensions.
- The inspector provides exact numeric x/y/width/height editing for one object and numeric x/y delta
  movement for mixed selections. These controls provide a complete keyboard alternative to pointer
  drag/resize; invalid values are rejected without mutation.
- The palette creates complete fresh-ID boundaries with absolute geometry and a color token.
  Boundaries render as labeled translucent background nodes, expose a small drag target and resize
  controls, remain selectable, and let ordinary cards and edges receive pointer events above them.
- Boundary title uses incremental Y.Text editing; color uses the validated atomic boundary command.
  Inspector help explicitly states that overlap and nesting have no meaning and boundary movement
  never moves cards.

## Atomicity and policy tests

- Document-model tests initialize two unequal nodes and exercise every alignment. Each expected
  position is asserted and each alignment emits exactly one Yjs transaction.
- The selection policy unit test covers full containment, partial overlap, disjoint rectangles, and
  zero-area edge contact.
- Existing geometry tests continue to prove mixed card/boundary batches validate completely before
  one transaction and leave state unchanged on invalid input.

## Browser evidence

A temporary Playwright observer drove installed Google Chrome through the real React Flow canvas,
editor commands, Web Lock, and IndexedDB persistence. The observer was removed after the passing run.

- Created and renamed two component cards and one boundary, changed the boundary color, and set its
  absolute x/y/width/height with the keyboard geometry controls.
- Shift-selected two cards and ran left alignment, observing identical world x coordinates. Added the
  boundary to form a mixed selection, moved all three by +32/+16 through one keyboard action, and
  observed each absolute position change by the same delta.
- Selected and moved the boundary alone by 48 world units; both card coordinates stayed unchanged.
- Dragged a card with grid snapping at 120% zoom and observed 16-unit world coordinates. Repeated the
  gesture while holding Alt and observed unsnapped world coordinates.
- Resized a selected card through React Flow's bottom-right control and observed grid-aligned width
  and height. Static callback tracing confirms pointer changes only update local React state and the
  session geometry method is reached from drag stop or resize end.
- Clicked the boundary's real header target after overlapping content existed, proving that the
  background surface does not block ordinary card interaction while the label remains selectable.
- Reloaded and recovered all three canvas objects and the edited boundary title from IndexedDB. The
  hydrated projection supplied the persisted geometry and color through the same adapter exercised
  before reload.

## Accessibility evidence

- React Flow keeps named, focusable targets for cards, edges, and boundaries. Selected objects have a
  visible ring in addition to color, and the inspector reports the selection count.
- Boundary title/color and geometry fields use associated labels. Alignment, move, and apply actions
  are semantic buttons with disabled read-only states and visible focus treatment.
- Numeric world-coordinate controls cover move and resize without pointer input. Boundary help
  explains non-containment, and geometry outcomes/errors use the existing live status region.
