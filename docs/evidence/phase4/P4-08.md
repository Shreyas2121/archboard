# P4-08 — Atomic browser outbox and inbound log

- Commit subject: `feat(sync-client): persist collaboration outbox atomically`
- Parent: `7c01a09a1d8de4cc006d0f89bd662415b1bf20f8`

## Baseline and implemented boundary

The existing version-1 IndexedDB adapter already inserted local log and outbox bytes together, retained pending entries through snapshot cleanup, and kept hydration/remote/local Yjs origins separate. P4-08 closed the remaining durability gap: ACK handling assumed the corresponding local log row still existed, but local snapshot cleanup can remove that row while its outbox entry remains pending.

The version-2 database adds durable receipt and received-sequence stores without replacing existing snapshots, logs, outbox entries, or namespace keys. An ACK now writes its receipt, advances the received sequence monotonically, and removes only its matching outbox entry in one transaction, even after the local log row was compacted. Duplicate ACKs preserve the original receipt; a conflicting sequence is rejected. Inbound updates write their log row and received sequence atomically without creating an outbox entry. Duplicate generated update IDs cannot overwrite an earlier pending entry or reuse an acknowledged ID. Namespace deletion includes the new stores.
