# P4-04 — Isolated collaboration update validation

- Planned commit subject: `feat(api): validate collaboration update candidates`
- Parent: `0e16e47ef5a25b2623175a3cdb5fd29f73a26741`
- Branch: `phase-4-durable-collaboration`

## Behavior proved

The worker clones the accepted Yjs state, applies client bytes only to the candidate, checks the pinned causal compatibility wrapper, validates physical graph roots and all entities against the accepted document, then bounds the encoded candidate to 10 MiB before returning it. The pool rejects updates above 1 MiB and accepted states above 10 MiB before admission, snapshots caller-owned buffers even while queued, admits at most two workers and a 20-job queue, and terminates any worker after two seconds. Operational defaults now reference the shared contract limits. Worker failures return safe generic messages without graph paths or raw data.
