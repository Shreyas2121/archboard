## Behavior proved

A single-flight registry opens each board once, caps active/opening rooms at 20 and reservations at 10 per board, serializes room work, and exposes idle eviction only after five minutes with no connections, pending work, or non-durable state. A failed opening leaves no partial room. The PostgreSQL loader reads board sequence, snapshot, and ordered update log in one repeatable-read transaction, checks sequence continuity, schema, byte bounds, causal completeness, and graph validity, and exposes only a fully reconstructed Y.Doc. Database outages receive a safe temporary error. Readiness now requires the dedicated writer lock and the update/receipt tables. Lock-session errors or failed heartbeat queries revoke readiness and signal process termination; the heartbeat uses the pinned direct connection.

## Contracts used

Shared Phase 4 room, connection, state, update, idle, and liveness limits; graph schema version 1; decimal-string server sequences; existing Yjs causal compatibility wrapper; PostgreSQL advisory lock key from Phase 1; TypeORM transaction-scoped reads. The board row remains the authoritative write-order boundary for later tasks.

## Database and socket evidence

Room reconstruction used a temporary schema with committed snapshot and update rows. Two loader instances returned sequence `1`, identical encoded Yjs state, and the expected graph. Missing update, sequence `2` after snapshot `0` without sequence `1`, malformed snapshot bytes, unsupported schema, and invalid physical graph each blocked admission. The database foundation integration proved a second independent direct session cannot acquire the advisory lock while the first owns it and can acquire it after release. Nest HTTP/auth WebSocket integration passed with lock-backed readiness. No production room socket was introduced in this task.
