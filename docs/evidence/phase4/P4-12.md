## Behavior and operations

The board editor retains its existing frozen, exportable local document and outbox on permanent server rejection or IndexedDB failure. Its new **Reload server version** action is available only to a ready writer. A confirmation dialog identifies the exact account/board/device namespace, warns that unacknowledged local work in that namespace will be deleted, offers a recovery download, and allows cancellation. Confirmation closes the socket and local persistence, deletes only that namespace while the Web Lock is held, then reloads the route. A native Chrome test verifies that another account's namespace remains intact.

The API's existing PostgreSQL advisory writer lock stops a second writer process at startup and makes `/health/ready` fail if ownership or schema readiness is lost. Existing room, connection, frame, presence-rate, and worker queue limits reject excess work. P4-12 emits JSON operational events for active socket/room counts, admission and validation rejection counts, database write and ACK durations, compaction duration/snapshot size, and client reconnect count. These events contain no board ID, user ID, cookies, update bytes, or document content. The verifier requires ignored paired pooled/direct database URLs; browser scripts use isolated migrated schemas and remove them on normal completion. Run `pnpm phase4:verify` from the root after configuring `.env` and `.env.local`; no production environment values belong in this evidence.
