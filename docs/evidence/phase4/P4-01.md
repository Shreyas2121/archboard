## Behavior proved

Every Phase 4 client and server wire shape has an exported strict Zod schema and inferred type. The existing Phase 1 event meanings remain compatible. A byte-frame parser rejects oversized frames, malformed UTF-8 or JSON, unknown events/fields, and invalid payloads with safe error text. Canonical nonempty base64 and PostgreSQL bigint decimal strings are bounded before costly processing. Presence counts and previews, server-supplied user fields, and error messages are bounded. Presenter event names are reserved but not accepted as Phase 4 client messages; `invalidate` retains its existing reserved server schema for future REST invalidation.

## Contracts used

Protocol version 1 and graph schema version 1; `hello`, `ready`, `update`, `ack`, `presence`, `access.changed`, and `error`; existing canonical error codes, UUID application IDs, graph points/colors/roles, and graph entity limits. New central constants cover 16 MiB frames, 1 MiB updates, 10 MiB state, 10 connections/board, 20 rooms/process, 20 updates/second with burst 40, 15 presence messages/second, two validation workers with a 2 second timeout and bounded queue, handshake/liveness/expiry, compaction, eviction, and reconnect delays. The internal validation queue cap is 20.
