# P4-07 — Compact snapshots and evict idle rooms

- Commit subject: `feat(api): compact collaboration snapshots safely`
- Parent: `e3be5c22c0ada3e9a1640b158a66f654ca13ddb9`

## Implemented boundary

Room maintenance checks active rooms every second. A dirty room compacts after 200 accepted updates or 60 seconds, through its board queue. The compactor locks the board row and atomically advances the full Yjs snapshot and `through_seq` while deleting update rows through that sequence. It leaves update receipts and checkpoints intact. A forward migration removes the old receipt-to-update foreign keys that would otherwise cascade-delete receipts during compaction; the receipt-to-board lifetime relation remains. The loader returns the snapshot sequence so a reopened room tracks pending updates correctly.

The maintenance pass evicts rooms only after five idle minutes, with no connections or queued work and durable accepted writes. Admission also clears eligible idle rooms before enforcing the 20-room cap. Eviction destroys the in-memory Y.Doc.

## Verification

- Real PostgreSQL migration, loader, compaction, and authenticated socket suites: **3 suites, 37 passed**. A15 committed an update, compacted away its update row, reconstructed the same graph with a fresh loader, and returned the original sequence on delayed duplicate retry.
- Injected failures after snapshot write and after update deletion rolled back to the old snapshot/log pair. A failure immediately after commit left the new pair. Every state reconstructed the same graph. Receipts and independent checkpoints survived successful compaction.
- Against an unmigrated schema, the compactor detected the legacy receipt cascade and rolled back, preserving the original snapshot, update, and receipt.
- API unit suite: **11 suites, 70 passed**. Registry and maintenance tests cover count and interval triggers, failed-compaction retry, idle/queue/durability eviction gates, admission capacity, reclaiming idle capacity, and eviction of unrelated rooms after a compaction failure.
- API build, typecheck, repository lint, formatting, and `git diff --check`: **passed**.

Database tests used temporary schemas. The forward migration must be applied before enabling compaction against an existing deployment schema.
