# P4-09 — Ordered WebSocket synchronization client

- Commit subject: `feat(sync-client): synchronize authenticated boards`
- Parent: `8d6cb96`

## Implemented behavior

`OrderedSyncClient` uses the browser WebSocket cookie behavior and the configured WebSocket origin to open `/ws/boards/:boardId`. It sends the shared version-1 `hello`, validates every incoming JSON envelope with the shared strict schema and frame limit, persists and merges a complete `ready` snapshot, then sends locally committed outbox entries in local-sequence order with one update awaiting ACK. The local persistence adapter remains the sole IndexedDB writer. The transport sends the exact stored update bytes and ID on retry.

Inbound broadcasts advance only in server-sequence order; old duplicates are ignored and a gap closes the socket for a fresh full `ready`. ACK handling uses the atomic P4-08 receipt transaction. A lost ACK can therefore resend its original ID and bytes after a later `ready` already includes the update. Reconnect uses exponential delay from one to 30 seconds with jitter; browser `online` only starts an earlier attempt. `CAUSAL_GAP` gets one fresh-ready retry of the same entry, then pauses. Other permanent errors and access downgrade preserve pending bytes and stop dependent sends. Status derives device save, offline cache, connection, synchronization, server receipt, storage error, access, and recovery states.
