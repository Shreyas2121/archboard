# P4-06 — Integrate board access and archive changes with rooms

- Planned commit subject: `feat(api): enforce live room access changes`
- Parent: `23f0af4356edea2676e73922ce679144d33e2281`

## Implemented boundary

The Phase 3 board service now notifies the collaboration gateway after archive, restore, member role change, and removal transactions commit. The gateway serializes active-room refreshes through the room queue and re-reads the shared permission service. Authorized sockets receive `access.changed` with their current role and archive state; removed members receive a null role and a policy close. No socket frame is written while a board transaction is open. The graph update path continues to recheck role and archive under the board row lock, so a delayed or missed notification cannot authorize a write.
