# P4-10 — Authenticated board editor

- Commit subject: `feat(web): connect authenticated board editor`
- Parent: `2a84886`

## Baseline and implemented behavior

The Phase 3 dashboard existed, but this tree had no `/boards/:boardId` route or dashboard link into an editor. The only editor session was the separately namespaced, locally seeded `/demo`. P4-10 adds the authenticated route and reuses that editor's Y.Doc, commands, projection, Web Lock, IndexedDB adapter, and React Flow canvas. It does not seed an authenticated board from the demo fixture.

The board route verifies the current user, opens the account/board/schema local namespace first, then checks REST board metadata before starting the cookie-authenticated WebSocket. Cached role and archive state permit a known editor to work from a cached copy when the network is unavailable. A missing local copy reports unavailable offline. Viewer, archived, access-denied, recovery, storage-error, narrow-screen, and second-tab states disable graph controls; `EditorSession` also rejects mutations, history changes, and text access at its command boundary. The server remains the write authority.

The shared editor displays connecting, local saving, pending count, server receipt, offline cache, viewer, archive, access change, and recovery labels according to persistence and transport state. The current graph and pending outbox remain visible for local recovery. `/demo` retains its local-only namespace and reset control and opens no collaboration socket.

A real-browser run found a fresh-board causal gap: `createGraphDocument()` writes its schema clock before the persistence listener attaches, while later local Yjs updates depend on that clock. The first authenticated edit was rejected twice with `CAUSAL_GAP`. The editor now captures those exact initialization bytes and commits them as the first outbox entry only after owner/editor authority is known, before later edits can send. An initial outbox/receipt marker survives ACK and reload, so an aborted first transaction can be detected and retried. The live rerun converged. The sync-client browser suite includes regressions for the ordered bootstrap and aborted-bootstrap reload.

## Browser and recovery observations

Three independent Chrome browser contexts opened the same board as owner, editor, and viewer. The owner created a component, the editor received it and created a note, and the owner received the note. Each sender reached “Saved to server” after its ACK. The viewer's create control was disabled. A second tab sharing the owner's local namespace became read-only. After the owner's context went offline and the test server terminated its sockets, the owner displayed “Offline · cached copy”; reconnection restored “Saved to server.” Archiving the board through the real API changed the live owner's status to “Access changed · local changes preserved” and disabled creation. A separate `/demo` page saved locally and opened zero collaboration sockets.

The permission suites exercise server-side owner/editor/viewer and archive authority. The served browser exercise did not inject a local quota failure or a permanent graph-validation error into the UI; the sync-client native-browser suite covers those underlying transport and persistence transitions. Offline direct-route asset loading and the finished account-revocation UX remain Phase 5 work. Broader throughput and crash measurements remain with the Phase 4 acceptance gate.
