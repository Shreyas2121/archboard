## Implemented

- `apps/web/src/app/editor/editor-shell.tsx`: retains the 56px toolbar, 44px footer, and 320px inspector; creation panel is 224px and collapsed rails remain 56px. All four panel combinations use the corresponding grid widths. The shell uses viewport height without the former 576px minimum; panel content scrolls independently.
- Creation tools use one “Add to board” heading and five full-width ghost rows with a minimum 48px height, 14px labels, and 12px descriptions. Existing click-to-create handlers, disabled states, creation errors, grid snapping, IDs, limits, and command calls remain intact. No drag-to-create affordance was added.
- Notices now occupy one bounded, scrollable region above the canvas instead of competing absolute top/bottom positions. Offline details, writer-lock retry, permission/session warnings, narrow-screen warning, command notices, and recovery export errors remain visible in deterministic order. Offline details reuse the existing truthful status policy. Recovery errors belonging to the central recovery panel stay there. Empty-board messaging does not appear on top of loading/recovery states.
- Canvas state/recovery panels have bounded scrolling, viewport gutters, a restrained surface, and a recovery button that can wrap in a small canvas. The canvas measurement ref moves to the actual canvas region below notices, so creation/fit/zoom calculations still measure the visible canvas. Those coordinate formulas and command calls were not rewritten. The shell's muted canvas tint is removed in favor of `surface-canvas`; the remaining React Flow wrapper tint is owned by UI-05.
- Footer zoom text uses 12px tabular numerals. Grid snap and Minimap keep their pressed-state styling and remain available as compact, named controls below 640px, with visible labels at wider widths. View control handlers are unchanged.
- `apps/web/src/app/editor/editor-toolbar.tsx`: flexible identity/status and action columns replace absolute centered status. Board title is a breadcrumb-style label with full accessible text/title; status is quiet text with its existing tone cue. Small screens use a compact mark, title, and up to two status lines. Undo/redo are separated from utility actions. Existing utility handlers, availability rules, responsive action visibility, and mounted button refs remain; actions were not moved into a menu. UI-02's compact theme selector remains shared.
- `apps/web/src/app/editor/editor-inspector.tsx`: one “Properties” heading, selected-object fields first, Geometry/Connections groups next, object/clipboard actions last. Empty and multiple-selection compositions leave commands reachable; Paste remains available with no selection and Copy retains its existing read-only availability.
- `apps/web/src/app/editor/editor-inspector-section.tsx`: shared Radix Collapsible composition with named button and chevron. Groups start open. Content stays mounted while visually collapsed, preserving geometry drafts and connection-flow state. Geometry errors continue to surface in the notice region and connection validation errors remain in the existing dialog.
- `apps/web/src/features/editor/history/editor-actions-panel.tsx`: quieter compact actions and a section divider, with the structural Undo and deleted-object recovery explanation retained at 12px. All command callbacks and disabled predicates remain unchanged.
- `apps/web/src/features/editor/inspector/card-inspector.tsx`, `product-text-field.tsx`, and `atomic-select-field.tsx`: 8px label gaps, 16px related-field spacing, 12px counters/helpers, readable sentence-case metadata, and full wrapped selected titles. ProductTextField composition/IME handlers, commit/cancel behavior, text-history boundaries, ARIA associations, limits, and access checks are unchanged.
- `apps/web/src/features/editor/boundaries/boundary-inspector.tsx`, `connections/edge-inspector.tsx`, `connections/keyboard-connection-flow.tsx`, and `selection/selection-geometry-panel.tsx`: matching field spacing and metadata scale, lighter section dividers instead of nested boxes, sentence-case dimension labels, and wrapping alignment actions. Boundary semantics, immutable endpoints/reconnection guidance, keyboard endpoint review, geometry operations, and validation/error paths remain intact.
- `apps/web/src/app/editor/editor-dialogs.tsx`: 448px confirmation maximum widths, 576px keyboard help, stacked shortcut rows on small screens, tabular shortcut labels, and the structural Undo/recovery explanation in help. Confirmation requirements, download actions, Escape/busy policies, and focus-return handlers remain. `local-storage-dialog.tsx` was audited; it already uses 512px width and the foundation primitives, and retains its storage/recovery information without a source change.
- `apps/web/src/app/editor/editor-layout-constants.ts`: initial compact viewport query for 768–1023px and documented layer order. Notices consume layout space; canvas state panels use z-10, toolbar/footer z-20, and shared Radix dialogs/menus z-50. Canvas presence/minimap integration remains UI-05 and update-prompt integration remains UI-06.
- `apps/web/src/features/editor/state/editor-ui-store.ts`: one-time palette initialization through the existing Zustand UI store. Editor entry samples the compact viewport query; repeated initialization, StrictMode effects, subsequent viewport changes, and remounts do not overwrite user toggles. A toggle before initialization also takes precedence. A store factory permits focused Node verification; production still uses one store instance. No durable graph content is added to UI state. `use-narrow-screen.ts` and the below-768px read-only policy are unchanged.
- `apps/web/src/features/editor/state/editor-ui-store.test.ts`: five Node cases verify initial open/closed defaults, one-time initialization, user toggle preservation, and isolation from inspector/view/selection/dialog state.
