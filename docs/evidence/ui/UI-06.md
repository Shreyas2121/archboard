# UI-06 Integration

Date: 2026-09-30. UI-01 through UI-06 implementation and focused non-browser verification are complete. Browser/visual acceptance remains pending. This record is the current integration handoff; earlier package records describe their original handoff state.

## Integration changes

- `apps/web/src/main.tsx`: one viewport-height flex composition reserves an application-update row above the route area. The route area has a definite remaining height and permits ordinary page content to overflow into document scrolling. The existing router and its scroll-restoration configuration are unchanged. SessionBoundary now mounts inside the existing ThemeProvider/TooltipProvider alongside the other application surfaces; QueryClientProvider and account-transition ownership remain unchanged.
- `apps/web/src/platform/update/app-update-prompt.tsx`: the update prompt uses a panel-surface row with a concise icon/title, paired blocked/error/success presentation, visible busy state, and wrapping actions. It scrolls independently above a 40dvh maximum so a review cannot consume the entire editor. It no longer has a fixed position or z-50 layer competing with dialogs, footer controls, minimap, or presence. Later remains a secondary action; Review/Update remains the primary action. Worker discovery, current-worker identity checks, compatibility checks, account pending-work inspection, export conditions, active-editor preparation, pending-work revalidation, activation, close/reload, cancellation on failure, and busy/disabled predicates are preserved.
- `apps/web/src/app/editor/editor-shell.tsx`: fills the route area's available height instead of independently consuming another full viewport. Its 56px toolbar, 44px footer, panel dimensions, notice reservation, measured canvas ref, and geometry/creation/fit/zoom formulas remain intact. Showing or dismissing an update changes the actual available canvas area through normal layout.
- `apps/web/src/app/editor/editor-layout-constants.ts`: documents the reserved update row and the existing dialog layering. Radix dialogs still portal above application content, including the update row, using the foundation overlay and focus behavior.
- `apps/web/src/app/routes/home-route.tsx`, `boards-entry-route.tsx`, and `app/components/page-state.tsx`: use the route area's full minimum height. Home, online/offline dashboards, and route/session states therefore share the same height contract when an update is present. Their actions, loading/error/session logic, and existing theme control remain unchanged.
- `apps/web/src/app/routes/board-editor-route.tsx`: remaining offline-editor checking/unavailable/cache-error states now compose PageState, bringing them into the shared type hierarchy, brand, responsive spacing, and Light/Dark/System control. Existing state-specific explanations, retry callbacks, cached-board/demo links, route validation, online/offline loading, permissions, and session ownership are preserved. Checking retains a reduced-motion-aware spinner; offline states use a decorative Lucide icon.
- `apps/web/src/features/auth/pending-changes-dialog.tsx`: preserves the full local-data/privacy and recovery explanation, highlights Download recovery as the primary action in a dedicated panel, and uses persistent paired error/success/busy feedback. Cancel/Retain/Clear actions stack on small screens and use a two-column footer on wider screens; the destructive action can wrap. The dialog remains 512px maximum with the foundation's viewport gutters/scrolling. Recovery bytes, export-success prerequisite for clearing, clear/retain callbacks, disabled state, controlled close/busy policy, and sign-out/account-switch confirmation requirements are unchanged.
- `apps/web/src/app/editor/local-storage-dialog.tsx`: keeps the 512px Radix composition and storage caveat, gives local-copy/write status a clear panel, and presents cached dates, pending-server count, and usage/quota as a responsive definition list with 12px labels and tabular values. Read/export errors stay persistent and descriptive. Refresh stays secondary; Download in-memory recovery is primary and wraps. The asynchronous read/cancellation, estimate fallback, report/session matching, availability predicates, demo/server distinctions, date formatting, recovery export, disabled predicates, and explicit return-focus ref remain unchanged.

No dependency/configuration upgrades, API/database changes, alternate styling/theme systems, placeholder capabilities, schema/durable graph changes, permissions changes, or persistence/history rewrites were introduced. Existing UI-01 through UI-05 edits and user planning files are preserved; changes remain uncommitted.

## Consistency review

- All primary pages and offline editor states use the existing shared theme provider and explicit Light/Dark/System control. Pending-change/storage/update surfaces consume the paired foundation tokens.
- Text hierarchy is consistent: 20px dialog headings, 14px ordinary copy and controls, and at least 12px labels/metadata at 100% zoom. The home hero and canvas monospace bodies retain their intentional scales.
- Targeted searches found no remaining sub-12px arbitrary text utilities, `transition-all`, duplicated muted canvas tint, or route-owned viewport-height utilities. The app frame owns viewport height; bounded dialogs and the update row retain viewport maximum sizes.
- Foundation primitives retain the checked-in Radix Nova composition, visible focus, selective primary actions, and reduced-motion handling. Board action menus, editor controls, saved colors, and presence use the previous packages' established treatment.
- Update and editor notices consume layout space. Dialogs and menus retain their shared portal layer. Source review confirms update/sign-out/storage guards were not replaced by presentation logic. Actual keyboard/focus/layering behavior still requires the deferred browser checks.
