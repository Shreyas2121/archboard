## Implemented behavior

- Owners/editors can resolve/reopen through a named confirmation using the captured
  thread version. Current editors can edit/delete their own live messages; owners
  can moderate other authors' live messages. Viewers, including former authors,
  have no write authority. Fresh account/membership/archive/online checks run again
  before each send. No authorship, timestamps or creator metadata are sent in a body.
- Edit forms use shared body validation and Unicode counters. Owner moderation keeps
  the original author. Delete confirmation explains the permanent marker; deleted
  rows have no edit/delete/resurrection controls. Existing edited/deleted labels are
  retained and thread summaries show resolution actor/time from server results.
- Added a memory-only moderation state coordinator. A form captures the original
  resource/version and typed body. A 409 fetches the current resource, shows its
  version/content beside the unsent edit, and requires explicit reviewed retry or
  cancellation. Reading current content never silently replaces the pending version
  or merges text. Another race on explicit retry returns to review again.
- Failed/uncertain versioned mutations preserve the edit and require a successful
  current-resource read before retry. Resolution is never applied optimistically.
  Commit announcements and draft clearing follow only a confirmed response. Duplicate
  clicks and cancellation during a flight cannot send a second mutation.
- Current-resource reads traverse existing cursor endpoints; thread reads omit the
  resolution filter so a thread moved to the other filter remains reviewable. No
  individual GET endpoint was invented. Successful review and committed writes
  invalidate scoped P6-04 comment prefixes, refreshing summary/detail/filter pages.
- Cancelling/reopening an edit retains its unsent text and original version. Cancelled
  edits also remain readable/copyable in a Retained unsent edits section, including
  after the source message becomes a marker. The UI states reload/navigation loss.
  Drafts stay separate from Y.Doc, graph history, graph exports, outbox, IndexedDB
  and service-worker caches. No previous-body history or cross-account transfer.
- Creation recovery retains the exact original UUID key, body and target. An uncertain
  request cannot unlock edited/new-key submission on a failed retry preflight or
  permission rejection. `IDEMPOTENCY_CONFLICT` also cannot authorize a replacement key.
  While the conservative 23-hour retry window is valid, explicit retry sends the
  original payload/key. Nothing sends automatically on reconnect.
- After that window, a recovery dialog must finish inspecting visible results for
  the same key **after expiry** before offering deliberate new submission. Reply
  inspection traverses all message pages; thread inspection traverses unfiltered
  thread pages, matches stable anchor identity, and inspects the first message.
  Similar text does not prove the original outcome; the dialog explains edited/
  deleted/missing matches and duplicate risk. Inspection never issues a mutation.
  Explicit permission to start anew retains the draft, then a separate Send action
  creates the new key. Pre-expiry, failed or mismatched-key inspections cannot unlock it.
- Account/access/offline/archive/viewer/narrow-screen changes suspend work. Old-scope
  late responses cannot clear a retained draft, announce a commit or populate a new
  scope. Protected read failures recheck authoritative access using the established
  denial/recovery path. Inaccessible account data is hidden; cached authorized data
  and memory drafts retain existing offline labeling rules.
- Dialogs reuse Radix/shadcn focus trapping, creation-trigger return focus and explicit
  moderation opener/tab return focus. Footer buttons wrap within the dialog width.
  Content renders as inert React text. The sidebar layout correction remains intact.
