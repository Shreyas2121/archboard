## Behavior proved

Committed thread creation, replies, message edits/deletion, and resolution/reopening
publish `comments` hints. Exact creation retries, current-version no-ops, denied requests,
and rolled-back writes publish none. Metadata changes publish `metadata`; membership
changes and invitation acceptance publish `members` and `metadata`. Unchanged metadata,
archive state, roles, absent removals, and repeated acceptance do not manufacture events.
Notification failure preserves the successful committed HTTP result and receipt.

Real independent cookie-authenticated sockets receive authorized hints. A reader socket
consumes a comments hint and performs a real authenticated REST refetch, observing the
committed thread and later message/resolution state. Other-board sockets receive none.
Removal and session expiry stop hints; removed/expired readers also lose REST authority.
Access notifications precede corresponding resource hints. A removal committed while
graph delivery waits also stops the removed socket from receiving protected UPDATE bytes.

Node tests with the actual TanStack Query client prove filtered thread lists, summaries,
and message-page keys under the resource prefix become stale and active queries refetch.
Hints coalesce, including a trailing refresh when another hint arrives during a fetch.
Authenticated ready/reconnect and online recovery refresh relational views; local actor
mutation and invite acceptance methods refresh without a socket. Failed REST queries stay
invalidated. No hint is treated as proof that REST data is current.

## Database, session, and socket evidence

The post-commit callback enters the existing board room queue. Access changes refresh
authority and disconnect denied sockets before the resource callback. Each recipient's
hint delivery checks the current session and reads locked board authority in the reused
transaction boundary. Authorized role/archive changes emit access state before hints.
Joining sockets defer hints; authenticated ready triggers full REST reconciliation.
Failure closes affected connections rather than granting authority from stale state.

A real insert barrier holds a new comment before commit: independent PostgreSQL readers
see no committed rows/receipt and sockets see no hint. Release produces the committed
HTTP result and hint. A real false CHECK constraint forces rollback with a safe 503 and
no hint. A notification-port failure separately proves commit/receipt survive failed
best-effort fanout. Exact replay still returns the stored result without another hint.

A delayed post-commit resource callback lets actual HTTP member removal commit first:
the removed socket closes without comments hints, authorized readers receive them, and
removed REST reads return 404. Actual session expiry before fanout produces socket
closure/no hint and REST 401. Actual invitation acceptance upgrades a viewer, emits
access state before membership/metadata hints, and emits nothing on exact retry.

The graph race uses the production AFTER_COMMIT_BEFORE_ACK failpoint, actual owner WS
UPDATE, and a concurrently committed HTTP removal. After PostgreSQL confirms membership
gone, the barrier releases: queued protected delivery rechecks locked authority and
disconnects the removed reader without UPDATE; the writer receives its durable ACK.
This proves the recipient race at fanout and does not close the broader Phase 4 audit.
