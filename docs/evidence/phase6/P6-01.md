## Contracts used

- Strict node/edge/point anchor union reuses application UUIDs and the finite, bounded graph
  `pointSchema`. Node labels use the node title limit; edge labels use the edge label limit.
  Missing/unknown fields, boundary targets, and malformed coordinates are rejected. Node/edge
  labels and positions are submitted wire context, never trusted fallback authority.
- Plain-text messages allow 4,000 Unicode code points, matching pinned Zod 4.6.4 string length
  validation. `countCommentBodyCharacters` supplies the UI counter rule. Whitespace counts;
  blank/whitespace-only input fails; nonblank formatting is unchanged. No normalization or
  grapheme counting is introduced. Supplementary Unicode characters are exercised at the limit.
- Limits are 2,000 threads per board and 500 messages per thread, including deleted rows.
  This task exports the limits; transactional enforcement belongs to P6-02.
- Requests contain only `anchor/body`, `body`, `body/expectedVersion`, `expectedVersion`, or
  `resolved/expectedVersion`, as appropriate. Versions are positive safe integers; PATCH
  resolution is a literal JSON boolean. Client authorship, timestamps, IDs, and versions on
  creation are rejected. Auth identities reuse `userSummarySchema`, accepting opaque text IDs.
- DTOs expose original author/creator summaries, UTC timestamps, versions, edit/deletion
  timestamps, resolution actor/time, and persisted anchor context. Resolution actor/time must
  agree. Summaries include `messageCount` and `latestMessage` author/body/time/deletion state.
  Atomic-create results return `{ thread, comment }` inside the standard object envelope.
- Deleted full/latest-message DTOs require `COMMENT_DELETION_MARKER` (`Message deleted`) as
  body. No original body is exposed. `deletedAt` determines deletion state, so an author may
  legitimately type the same marker text in a live message. Preventing resurrection is a
  server mutation responsibility for P6-03.
- Lists reuse canonical base64url timestamp/UUID cursors and default/max page sizes 30/100.
  Thread `resolved` query accepts only strings `true`/`false`; omission means all states.
  Thread order is `(createdAt,id)` descending; message order ascending. The same cursor
  payload supports both, with the directional comparison owned by the repositories.
- Existing error codes/envelopes are unchanged: validation/missing committed target use
  `VALIDATION_ERROR` 400; authentication 401, role 403, nonmember/path-scoped resource 404,
  archive/version/idempotency conflict 409, payload/cap rejection `PAYLOAD_TOO_LARGE` 413,
  rate limit 429, temporary failure 503. Target membership/committed existence cannot be
  established by wire validation and must be checked in P6-02.
- Existing member/invite and WS contracts remain unchanged, including `invalidate` resources
  `metadata`, `members`, `comments`, `checkpoints`; no `invites` resource is added.
