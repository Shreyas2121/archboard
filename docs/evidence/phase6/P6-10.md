## Behavior proved

- Scoped board reads fence both request start and completion. Metadata, members,
  invitation lists, thread/message pages and accepted-board refresh cannot return
  protected data after cancellation or identity/access loss, even if an adapter
  finishes after abort. Query prefixes remain deployment/account/board/resource scoped.
- Sharing reads/writes consult the current selected account, pending local sign-out
  marker, session query identity/status and editor denial before proceeding. Late
  discussion creation, invitation and moderation results cannot clear drafts or
  expose results in an inactive account. Scope-keyed forms retain the existing
  memory-only draft lifecycle and explicit navigation/reload limitation.
- Socket access removal now marks the editor itself denied before forwarding the
  resource event. It freezes graph commands/uploads and hides protected discussion/
  sharing content; graph document bytes remain unchanged. Existing scope cancellation
  and cache removal handle the relational views, without deleting local graph storage.
- A successful session check returning null clears protected queries. Pending local
  sign-out also clears them before attempting the existing cookie invalidation flow.
  A valid cookie with an unsuccessful server sign-out never selects that account again.
- Authenticated room ready/reconnect, online recovery and window focus use one
  recovery composition. It first cancels ongoing board reads and invalidates downloaded
  views without fetching, then checks the existing session query before fetching
  active relational views. Failed, signed-out, superseded, disposed or now-offline
  session results cannot authorize recovery. Cleanup removes event/room listeners.
- Protected queries disable independent automatic focus/reconnect fetching. Explicit
  invalidation controls freshness (`staleTime: Infinity`); discussion/message stale
  labels also observe invalidation, not just network errors or active fetches. A
  successful REST response establishes freshness; graph readiness/sequence does not.
- Offline reads retain previously downloaded memory data with fetch time/stale labels;
  uncached data retains the unavailable state. Offline transitions cancel board reads.
  Recovery has no mutation port and never sends a discussion draft automatically.
- Existing viewer/archive write guards, version/conflict review, exact uncertain
  creation requests, owner-only invitation handling and preservation-aware self-leave
  continue to pass focused regressions. The established invitation-list API still
  uses active-owner management authority; archived invitation metadata remains a
  labeled cached view, while authorized board/member/discussion reads continue.
