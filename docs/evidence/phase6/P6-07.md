## Behavior proved

Implemented `/invite/:token` using the existing router, PageState, Button, session
query and Better Auth social sign-in. The route checks canonical token syntax,
shows no board preview before sign-in, and renders signed-out, session loading/error,
preview loading/ready, accepting/accepted, expired, invalid-or-revoked, exhausted,
archived, already-member, offline and expired-session states. Preview exposes only
board title, inviter name, offered role and expiry. Text uses inert React rendering.
Controls have names and status/error announcements; rendered accessibility is UNRUN.

Acceptance is an explicit button action. Each preview and acceptance refreshes the
session through the existing account-preservation boundary and checks the captured
actor. The account/invitation subtree is replaced on identity changes; disposal
aborts operations and suppresses late results. Offline blocks mutation and labels
retained in-memory preview with its fetch timestamp as possibly stale. Reconnection may refetch session and
preview but never automatically accepts.

A lost acceptance retains an unconfirmed state and an explicit confirmation action
for the same actor/token. Exhausted preview also offers explicit recorded-user
confirmation, allowing safe recovery after reload without inventing a second server
acceptance policy. The recorded accepting user succeeds; another account remains
exhausted under the existing API. Successful acceptance invalidates relational keys,
fetches current board metadata/effective role and the account's default board-list
pages, then navigates to the returned board ID. Refresh/navigation failure retains
the accepted result; Open retries reads/navigation rather than submitting acceptance.

The frozen acceptance DTO has no prior-membership flag. The already-member message
is shown when immutable owner role or an editor role retained from a viewer offer
proves previous access. Same-role/new/upgrade results use the ordinary accepted
state; the UI does not guess prior membership from stale account caches. Server
no-demotion/upgrade/owner-no-row rules remain unchanged.

Sign-in uses a shared helper that permits only `/boards` or a canonical same-app
invite path. The validated callback is constructed under the current application
origin; no browser token store is added. Home's existing continuation also supports
that strict path. Session sign-out/account-switch preservation is reused rather
than bypassed. No token, callback, private error body or stack is logged by these
features. Better Auth diagnostics retain only fixed event/severity; React and the
invite view boundary emit fixed messages. Scroll restoration uses a redacted invite
key and strips continuation queries from durable keys.
