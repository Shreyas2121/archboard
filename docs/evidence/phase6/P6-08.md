## Implementation

- Added the primary Discussion tab beside Properties in the existing inspector.
  The checked-in Radix Nova Tabs primitive was generated with the required
  `pnpm.cmd dlx shadcn@4.21.0 add tabs --yes --cwd apps/web`, then adapted to the
  existing `@/lib/utils` helper. The initial sandbox attempt reported EPERM;
  the approved rerun succeeded. No dependency, catalog or lockfile changes.
- Threads use unresolved/resolved filters and stable cursor pages; messages use
  ascending cursor pages. Both sit beneath the existing deployment/account/board
  `comments` query prefix. Loading, unavailable, empty, error/retry, fetch-time/stale
  views, author/time, latest-message/count, edited and deletion-marker states use
  shared DTOs. Adapters reject responses for different boards/threads.
- Added named selected-card/connection actions, keyboard-operable world X/Y inputs,
  and viewport-center point creation through React Flow's screen/world converter.
  Boundaries and mixed selections cannot supply object anchors. Node centers and
  edge endpoint-center midpoints come from the local projection for UI only; the
  existing server reader still derives authoritative committed fallback context.
- Passive numbered canvas markers use world coordinates and current viewport.
  They have no pointer handlers, focus targets or keyboard shortcut listeners.
  Panel buttons focus available anchors through local selection and viewport only.
  Deleted anchors keep their server label/position and show “Original object deleted”
  with saved-position navigation. No graph command, resurrection or ID remapping.
- Create/reply forms use the shared 4,000-character Unicode limit and blank/body
  validation. The synchronous flight guard prevents double submits. Only a committed
  response clears that draft and announces sent; no optimistic sent messages.
  Actor mutations refresh discussion through P6-04 even without a socket.
- Logical requests retain their UUID key, target and exact submitted payload in
  memory. Uncertain outcomes lock context/content for explicit identical retry;
  failed preflight/denied retries cannot erase an earlier uncertain outcome.
  reconnect sends no mutation. Retry expires conservatively after 23 hours, without
  replacing the key automatically. Definitive rejections preserve a keyed draft
  per context while allowing another target; editing a rejected draft explicitly
  starts a new logical request. Object draft identity survives moves/renames.
- New local-target instructions explain the committed-graph requirement. The API's
  object-target `VALIDATION_ERROR` becomes an explicit pending/deleted-target unsent
  explanation. No graph pending-count or empty-outbox gate blocks existing-target
  comments or points. Invalid world positions preserve drafts with field feedback.
- Reused account-scoped sharing metadata/member reads, fresh authority evaluation,
  and authenticated preflight. Viewer/archive/narrow-screen views have no enabled
  mutation controls. Offline/account/access changes abort pending requests; old-scope
  late results cannot populate another account's queries or drafts. Authoritative
  access reads reuse the existing denial/cache-clearing and graph recovery behavior.
- Drafts and discussion remain outside Y.Doc, graph outbox, exports, IndexedDB and
  service-worker caches. The UI explicitly explains memory-only reload/navigation
  loss. Tabs and inspector collapse retain the discussion component and drafts.
  `/demo` has no discussion feature. User text renders as React text, never HTML.
