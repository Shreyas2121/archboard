# C02 — Add validated configuration and named constants

Environment: Windows, Node.js 22.23.2, pnpm 11.24.0

## Behavior proved

The API and web applications parse their environment once during startup through strict Zod
schemas. The API rejects absent database URLs, invalid ports, malformed or non-canonical origins,
wildcards, duplicate allowlist entries, insecure production origins, and non-PostgreSQL database
URLs. Configuration errors name the invalid variable without retaining or printing credential
values. The web parser selects only its browser-safe API and WebSocket origins and ignores API-only
secrets.

Operational defaults now have one API-owned source for WebSocket handshake and heartbeat timing,
candidate-validation timeout/concurrency/queue depth, room admission, and content/presence rates.
Duration and rate names encode their units.

## Contracts used

- `PUBLIC_API_ORIGIN` is one exact HTTP(S) origin; production requires HTTPS.
- `ALLOWED_WEB_ORIGINS` is a nonempty comma-separated list of unique exact origins; production
  requires HTTPS.
- `VITE_API_ORIGIN` and `VITE_WS_ORIGIN` are browser-safe exact origins; production requires HTTPS
  and WSS respectively.
- HTTP and WS are accepted only for `localhost`, `127.0.0.1`, and `[::1]` outside production.
- `PORT` is a base-10 integer from 1 through 65,535.
- `DATABASE_URL` and `DATABASE_DIRECT_URL` accept only PostgreSQL URL protocols and are never
  included in validation messages.
- Phase 1 operational budgets from `plan.md`: 2-second validation timeout, 2 validation workers,
  10 connections per room, 20 active rooms per process, 20 content updates/second with burst 40,
  and 15 presence updates/second. C02 establishes a bounded validation queue depth of 32 pending
  jobs for later measurement in C13.

## Failure injection

Configuration tests inject missing values, malformed ports and URLs, origin paths, wildcard and
duplicate origins, unsafe production protocols, non-PostgreSQL database protocols, and database
credentials in invalid input. Every case fails before application startup, and credential text is
absent from the resulting error.
