# C05 — Implement the Yjs schema and projection

Commit: recorded in Git history by this evidence file's commit

Environment: Windows, Node.js v22.23.2, pnpm 11.24.0, Yjs 13.6.32

## Behavior proved

The document factory creates the nine fixed `Y.Map` roots and graph-only schema metadata. Fixture hydration stores entity IDs only as map keys, collaborative text as `Y.Text`, and geometry and step references as atomic values. Validation covers physical shape and every stored entity, including tombstoned values, and compares candidate documents with prior accepted documents for immutable fields, physical removal, and append-only tombstones. Projection is deterministic and filters tombstoned entities, incident edges with unavailable endpoints, and unavailable presentation-step targets. Missing logical graph references remain valid document structure and are not reported as causal gaps.

## Contracts used

The implementation consumes `GRAPH_SCHEMA_VERSION`, graph entity/projection schemas, `ERROR_CODES`, all field and entity limits, and `MAX_ENCODED_YJS_STATE_BYTES` from `@archboard/contracts`. It consumes the all-entity, minimal, and limit fixtures plus fixed UUIDs from `@archboard/fixtures`. Yjs is pinned exactly at 13.6.32.

## Failure injection

Tests inject wrong root types, scalar entities, invalid map-key IDs, false tombstones, non-`Y.Text` text, invalid stored node kinds, oversized tombstoned text, accepted-entity removal, immutable node-kind and edge-endpoint changes, and accepted-tombstone removal. Candidate validation rejects each case. The immutable and append-only checks compare independent candidate and accepted `Y.Doc` instances.
