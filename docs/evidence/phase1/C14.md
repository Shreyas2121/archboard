## Binding strategy

The Phase 1 spike uses a native plain-text `<textarea>` rather than a rich-text or contenteditable
framework. On each native `input` event, the binder compares the previously rendered value with the
browser value, finds their shared prefix and suffix, and applies only the changed range as a Y.Text
delete and/or insert in one local transaction. It never replaces the complete Y.Text value per
keystroke. A local-origin observer does not echo that edit back into the control.

For independent remote Y.Doc updates, the Y.Text observer walks the event delta, uses
`HTMLTextAreaElement.setRangeText` to patch only affected DOM ranges, and maps the focused control's
caret or selection through each insert/delete. The mountable harness is labeled as a Phase 1 spike
and is not wired into the product app or presented as a final card editor.

## Behavior proved

Seven browser-backed unit cases run against the native Chrome textarea and real independent Y.Docs:

- Local insertion yields one Y.Text delta with a retained prefix and a single-character insert.
- Local backspace yields one Y.Text delta with a retained prefix and one-character deletion.
- A second control bound to the same Y.Text receives the first control's local incremental edit.
- A remote insertion before the caret shifts the caret without losing focus or replacing local text.
- A remote insertion before a selected range and its later deletion shift the range out and back.
- A remote insertion inside the range expands its end while preserving its start.
- Concurrent local and remote inserts converge to the same string on both replicas and in the
  textarea, with the caret mapped to the resulting end.

Per the user's testing preference, these are unit-level browser-backed checks only. No frontend
integration or end-to-end suite was added or run.

## Browser matrix and limitations

| Browser                                 | Phase 1 status           | Evidence                                              |
| --------------------------------------- | ------------------------ | ----------------------------------------------------- |
| Google Chrome 153.0.8010.36 on Windows  | Supported for this spike | Seven native browser-backed units pass                |
| Firefox, Safari/WebKit, mobile browsers | Unverified               | Not installed or run in the current repository matrix |

Selection mapping is proved for plain UTF-16 textarea offsets and the tested insert/delete cases.
IME composition, emoji/grapheme-aware cursor movement, bidirectional text, mobile virtual keyboards,
and browser-specific selection behavior outside Chrome are not certified here. The spike also does
not enforce graph-field length limits; a production graph editor must route validated edits through
the document-model command boundary. Those are explicit later-work constraints, not claims of C14.
