# C01 — Bootstrap the workspace

Parent: root commit<br>
Environment: Windows, Node.js 22.23.2, pnpm 11.24.0

## Behavior proved

The repository is a strict TypeScript pnpm workspace with independently buildable React/Vite and
NestJS/Express applications, framework-independent shared package entry points, stable root
commands, formatting and lint policy, and package-boundary enforcement.

## Contracts used

- Phase 1 repository baseline and technology compatibility gate.
- Feature-module modular-monolith boundaries from `guide.md`.
- C01 does not define graph, protocol, persistence, or database contracts.

## Commands and results

- `pnpm install --frozen-lockfile` — PASS; all seven workspace projects resolved from the
  committed lockfile.
- `pnpm format:check` — PASS; all included files match the Prettier policy.
- `pnpm lint` — PASS; ESLint, the no-magic-numbers policy, and framework-boundary restrictions
  report no errors.
- `pnpm typecheck` — PASS; six projects pass strict TypeScript checks.
- `pnpm test` — PASS; Jest 30.5.1 and Vitest 5.0.0 start successfully and explicitly report that
  C01 contains no test files.
- `pnpm test:integration` — PASS; the reserved API integration-test runner starts and explicitly
  reports that C01 contains no integration tests.
- `pnpm test:browser` — PASS; the reserved browser-test runner starts and explicitly reports that
  C01 contains no browser tests.
- `pnpm build` — PASS; all four shared packages, the Nest API, and the Vite web application build.
- `pnpm --filter @archboard/api start` plus `GET http://127.0.0.1:3000/` — PASS; Nest starts and
  returns `{"name":"archboard-api","status":"available"}`.
- `pnpm --filter @archboard/web preview` plus `GET http://localhost:4173/` — PASS; the production
  preview returns HTTP 200 with the application root and module script.
