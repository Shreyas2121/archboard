# C09 - Prove authenticated WebSocket upgrades

Commit: recorded in Git history by this evidence file's commit

Environment: Windows, Node.js v22.23.2, pnpm 11.24.0, Better Auth 1.7.4, ws 8.21.3, Neon PostgreSQL 18

## Behavior proved

The production bootstrap disables Nest's automatic body parser, mounts Better Auth's Express 5 catch-all handler, and only then installs JSON parsing. Exact configured frontend origins receive credentialed CORS headers. Better Auth's session cookie and response headers survive that handler path.

The integration test creates a real database-backed Better Auth session through `POST /api/auth/sign-up/email`, extracts the actual HttpOnly session cookie from the response, and uses it on a native HTTP WebSocket upgrade. Email/password authentication is enabled only in test mode; production provider configuration remains outside C09.

The native upgrade listener validates the board path and exact Origin before resolving the real Better Auth session from the incoming Node headers. Session lookup is bounded by the named 5,000 ms handshake limit, and `ws` enforces the shared 16 MiB frame limit. No message is sent until a strict shared client envelope is parsed.

Because membership and room loading are C09 non-goals, a valid authenticated `hello` receives a strict shared `SERVER_BUSY` envelope without graph bytes. The spike deliberately does not invent a board role or authorization decision.

## Failure injection

The real upgrade harness submits no cookie, a tampered session cookie, and an exact but untrusted Origin. The server rejects them during HTTP upgrade with 401, 401, and 403 respectively, and no WebSocket graph channel opens.

An authenticated client sends a malformed non-strict `hello` and receives close code 1008 without a message. Another authenticated client sends a frame one byte above `MAX_WS_FRAME_BYTES` and receives close code 1009 without a message. The success case also observes zero messages before sending its valid shared `hello` envelope.

## Known gaps

GitHub sign-in, board membership authorization, room synchronization, graph snapshots, reconnect behavior, and presence are intentionally not implemented. The C09 transport returns a retryable `SERVER_BUSY` response after successful authentication until those later layers exist.

The current pinned `pg` stack continues to warn that `sslmode=require` semantics will change in pg 9; that major upgrade requires an explicit TLS-mode decision and renewed database/auth verification.

A [pre-C15 test-isolation fix](./C15-fix-isolated-integration.md) now removes the test's generated
Better Auth user by unique email during teardown; the live pooled cookie and WebSocket proof is
unchanged.

A separate [pre-C15 application-boundary fix](./C15-fix-auth-boundary.md) routes collaboration's
session lookup through auth's public application port. The live upgrade semantics are unchanged.
