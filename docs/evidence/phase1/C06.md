## Behavior proved

The public document-model API now provides validated commands for creating and editing every Phase 1 graph entity, moving/resizing/coloring and aligning nodes, incrementally editing collaborative text, replacing reconnected edges, atomically reordering presentation steps, and tombstoning all entity kinds. Creation accepts only complete contract-valid entities and one command produces one transaction. Commands reject missing, deleted, invalid, over-limit, reused-ID, and in-place identity-field changes before document mutation.

Deleted captures restore as fully initialized entities with fresh caller-supplied IDs. References between captured nodes, edges, and steps are remapped to the fresh IDs, while original entities and append-only tombstones remain unchanged.

Stable origins distinguish eligible local edits, local structural changes, remote updates, and hydration. The local undo manager tracks only local property, collaborative-text, and geometry commands. Creation, replacement, restoration, deletion, hydration, and remote transactions are excluded. Undo after an independent remote move removes the local rename while preserving the remote position.

## Contracts used

Commands consume the graph entity schemas, entity types, enum constants, geometry bounds, text bounds, step-reference constraints, and live entity limits from `@archboard/contracts`. They preserve the C05 fixed roots, `Y.Text` fields, atomic geometry/reference fields, immutable node kinds, immutable edge endpoints and handles, and append-only tombstone invariants.

## Failure injection

Tests submit non-finite geometry, an attempted in-place edge endpoint mutation, a reused/tombstoned ID, and an edit against a deleted node. Every proposal is rejected before the observable projection changes. Tests also invoke generic undo after creation and deletion and prove neither structural command is reversed.
