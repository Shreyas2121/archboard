# C12 - Prove atomic IndexedDB update and outbox storage

## Behavior proved

The React-free `@archboard/sync-client` package owns one versioned IndexedDB database with exactly four named stores: `localSnapshots`, `localUpdates`, `outbox`, and `boardCache`. Every key is scoped by a canonical namespace containing deployment origin, user ID, board ID, and graph schema version. Tests prove that changing any namespace component produces a distinct key and that one account cannot list another account's outbox.

Local Yjs command events reserve a local sequence and write the exact emitted update bytes to `localUpdates` and `outbox` in one native IndexedDB read/write transaction. The outbox also stores the SHA-256 hash of those same bytes, update ID, sequence, creation time, and pending status. The adapter reports `saving` until `transaction.done` resolves; only committed outbox records are returned as transport eligible.

ACK handling updates the matching local-log record with server sequence and acknowledgement time and removes its outbox record in one transaction. An injected abort between those operations leaves both the unacknowledged log record and outbox retry intact.

Hydration uses `COMMAND_ORIGINS.HYDRATION` and creates no log or outbox record. Remote application is persisted as a remote log record and applied with `COMMAND_ORIGINS.REMOTE`, without an outbox record. Local edit and structural origins are the only origins captured into the outbox.

Per the user's instruction, C12 adds no `apps/web` harness or frontend integration/end-to-end tests. The six persistence units run directly in a real headless Chrome browser so IndexedDB transaction behavior is native rather than mocked. The canonical `pnpm test:browser -- indexeddb outbox` command continues to route to those sync-client browser-backed units; C14 adds separate Y.Text browser-backed units.

## Failure injection

`AFTER_LOCAL_UPDATE_WRITE` aborts the native transaction after the exact local bytes are put into `localUpdates` but before the outbox put can commit. IndexedDB rolls back the first put as well. The A22 test proves zero local-log records, zero transport-eligible records, `savedOnDevice: false`, `editingPaused: true`, `PERSISTENCE_FAILED`, a throwing edit guard, and an export projection that still contains the in-memory node.

`AFTER_ACK_WRITE` aborts after acknowledgement fields are put into `localUpdates` but before outbox deletion. The test proves the acknowledgement fields are rolled back and the original outbox record remains eligible for safe retry.
