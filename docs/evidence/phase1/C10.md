# C10 - Reject causally incomplete Yjs updates

Commit: recorded in Git history by this evidence file's commit

Environment: Windows, Node.js v22.23.2, pnpm 11.24.0, Yjs 13.6.32

## Behavior proved

The API now exposes one server-side `assertCausallyComplete` compatibility boundary. Complete candidate `Y.Doc` instances pass; candidates with buffered missing structures, buffered delete sets, or both fail before they can replace an accepted document.

Yjs 13.6.32 has no supported public API for querying buffered causal dependencies. The wrapper therefore contains the only API application access to the pinned `Doc.store.pendingStructs` and `Doc.store.pendingDs` representation. It validates `pendingStructs` as `null` or `{ missing: Map<number, number>, update: Uint8Array }` and `pendingDs` as `null` or `Uint8Array`. Missing fields or unexpected value shapes raise `YjsCausalCompatibilityError` rather than being treated as complete.

Executable server-local fixtures generate both dependency patterns using public Yjs update APIs. Each fixture applies the dependent bytes first, proves the expected gap kind, then applies the missing dependency and proves the candidate becomes complete. The separate accepted document remains byte-for-byte unchanged throughout rejection.

## Failure injection

The structure fixture withholds an earlier clock from the same Yjs client and delivers the later structure first, producing `pendingStructs`. The delete-set fixture withholds the inserted item and delivers its deletion first, producing `pendingDs`. Both are genuine encoded Yjs updates rather than mocked store values.

The upgrade sentinel passes a document from the installed Yjs package through the compatibility boundary. A separate incompatible-shape case omits the pinned fields and proves the wrapper fails closed. Any Yjs upgrade that removes or reshapes these fields must break the mandatory test until the assumption is deliberately reviewed.

## Isolation check

A repository search found no `Doc.store`, `pendingStructs`, or `pendingDs` access elsewhere under `apps/api/src`. Fixture generation and all ordinary collaboration code use public Yjs APIs.

## Known gaps

The wrapper validates a candidate after bytes have been applied to that isolated candidate; C11 owns the acceptance pipeline that combines this check with durable persistence and commit-before-ACK behavior. Worker isolation, timeouts, and queue bounds are handled in C13.

The causal check is intentionally coupled to Yjs 13.6.32 internals because no public completeness signal exists in that version. Upgrading Yjs without running the sentinel is unsupported.
