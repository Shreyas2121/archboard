Environment: Windows, Node.js 22.23.2, pnpm 11.24.0, configured PostgreSQL direct and pooled endpoints. Integration tests use synthetic users and an isolated migrated schema. No real GitHub OAuth application was configured.

## Behavior proved

Production configuration rejects missing, placeholder, or malformed GitHub client settings with variable names and without credential values. Better Auth exposes GitHub social sign-in with `read:user` and `user:email` scopes. Email/password remains enabled only in test mode. Auth-owned `/api/v1/me` returns the strict `{ data: { id, name, email, image } }` response from a real Better Auth session cookie. Anonymous requests and forged actor headers receive the safe `UNAUTHENTICATED` 401 envelope with a request ID. Auth lookup failures produce a safe `TEMPORARILY_UNAVAILABLE` 503. Sign-out and an expired database session invalidate `/me`. An untrusted Origin is denied at the Better Auth handler boundary, while the handler still receives allowed requests before Nest JSON parsing.

## Contracts used

`CurrentUser`, `currentUserResponseSchema`, `apiErrorEnvelopeSchema`, and the shared error codes from P3-01. `AuthSessionLookup` supplies the trusted user, and the new `RequestActor` application port encapsulates Node header conversion and cookie lookup for HTTP controllers. The actor is never taken from request fields.

## Changed scope

`apps/api/src/modules/auth/**`, `apps/api/src/platform/config/**`, `.env.example`, and this evidence file. `scripts/phase1-verify.mjs` gained synthetic production GitHub settings because its secure-origin fixture now exercises required production configuration. The existing validation-worker test fixture uses a named 1.5-second fault-injection deadline after two aggregate runs exceeded its former 300 ms startup allowance; the production 2-second limit and every assertion remain unchanged. No provider application, database migration, frontend auth, or board service was created.

## Database evidence

The `/me` integration suite created a unique `archboard_p302_*` PostgreSQL schema through the direct connection, applied the committed foundation migration, exercised actual Better Auth user/session rows and cookies, set the test session expiry in the isolated schema, and dropped that schema in teardown. It used the direct endpoint for isolated test session semantics. The existing pooled-cookie WebSocket integration suite also passed.

## Authentication and security evidence

A test-only email/password signup obtained actual Better Auth `HttpOnly` session cookies. The same cookie authenticated `/me`; sign-out and database expiry each returned 401 on retry. A synthetic GitHub sign-in request produced an authorization URL at GitHub with only the two identity scopes; no real provider callback was attempted. The `/me` response contained no session token, provider account, or forged header value. Untrusted-origin credential POSTs returned no session cookie.
