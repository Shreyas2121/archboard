## Behavior proved

The infrastructure provides transaction-scoped board, member, invite, idempotency, and committed-graph repositories. Board row locking returns typed owner, membership, archive, version, and decimal-string sequence state. The user-row lock precedes active-owned-board counting. The initial snapshot is a validated schema-version-1 Y.Doc with exact byte length and sequence zero. Canonical nested JSON hashing is stable under object-key reordering and rejects non-JSON input. Idempotent callers serialize on a transaction-scoped advisory lock; identical requests replay one committed response, different payloads conflict, and expiry is determined by database time. One-time response data is excluded from the stored replay body.

The listing repository uses TypeORM queries and stable `(content_updated_at DESC, id DESC)` ordering. It retains PostgreSQL's full timestamp precision in `contentUpdatedAtCursor`; converting through JavaScript `Date` had failed the first real-database cursor test because microseconds were lost. The corrected cursor test passes.

## Database evidence

The suite creates a process-unique schema on the direct connection, migrates from zero with `synchronize: false`, and drops the schema in teardown. It confirms zero pending upgrades, rolls the foundation migration down, then reapplies it. Two independent QueryRunner connections race on one idempotency key: identical requests perform one effect and return equivalent safe responses; different payloads produce one effect and one conflict. Injected failure before response storage, and a database rejection during response storage, both roll back the board effect. A separate concurrent pair contends on the user-row lock at 99 active boards; one creates the hundredth and the other observes the cap. A committed snapshot decodes and validates, and its stored byte length matches the actual bytes.

Existing indexes cover owner-active lookup (`IDX_boards_active_owner_content_updated`), member-by-user lookup (`IDX_board_members_user`), invite-by-board lookup, and the idempotency primary key plus expiry lookup. The accessible-board query combines owner and membership predicates and sorts by content timestamp and ID. The fixture has approximately 100 visible rows and exercises cursor pagination and joined membership without duplicates. The owner index lacks ID as a tie-break column; with the bounded owner cardinality and no measured large joined-board workload, this task does not claim a new index is justified. P3-12 must record representative `EXPLAIN (ANALYZE, BUFFERS)` plans and timings on a larger mixed owned/joined/archived fixture and add a forward migration if the measured sort or scan warrants it.
