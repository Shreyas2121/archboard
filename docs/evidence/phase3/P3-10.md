## Implementation

The web app uses the exact catalog versions of TanStack Query 5.103.2 and Better Auth 1.7.4. A typed API client sends credentialed requests to the configured API origin, parses shared Zod response and error envelopes, supports abort signals, and classifies 401 separately from network, other HTTP, and invalid-response failures. The Better Auth browser client owns social sign-in and sign-out. Application code neither reads nor persists session cookies or tokens; source inspection found no `document.cookie`, `localStorage`, or `sessionStorage` use in the new auth/API/route modules.

Better Auth's shared URL helper imports server environment discovery into its browser client. The Vite build maps that unused lookup to an empty browser module because this client always receives an explicit API origin. The normal production asset scan then passed with 216 files inspected. A second served-build smoke check after the mapping confirmed the GitHub client request and its failure state.

The landing page waits for `/me` before showing signed-out content. Signed-in users go to `/boards`; unauthenticated visits to `/boards` return to the landing page with a bounded `/boards` return path. The route validates the return path again before use. Network/server failures show an announced retry state. Sign-out removes cached authenticated queries and returns to the signed-out landing page. `/boards` is a protected entry placeholder; the dashboard belongs to P3-11. The existing `/demo` route and its local document namespace were not changed.

## Browser evidence

Chrome 153.0.8010.53, headless on Windows with Node.js 22.23.2, served the Vite production build at `http://127.0.0.1:4173`. A test-mode build used `VITE_API_ORIGIN=http://127.0.0.1:4174` and `VITE_WS_ORIGIN=ws://127.0.0.1:4174` to permit local HTTP origins. Playwright intercepted only API responses. The browser run passed:

- Delayed `/me` displays the resolving state without a signed-out flash; 401 then displays the signed-out landing page.
- The GitHub button sends a Better Auth social request with provider `github` and a same-origin `/boards` callback; a synthetic 503 produces the announced error state.
- An external `returnTo` value is discarded; `/boards` redirects a signed-out visitor to the landing page with `/boards` intent.
- An API network failure displays retry; retry with a synthetic valid user reaches `/boards`.
- Authenticated refresh resolves `/me`; a subsequent 401 returns to sign-in with route intent.
- Sign-out returns to the landing page and clears the authenticated view.
- The demo's IndexedDB database remains present after the simulated auth transitions and the demo route remains reachable.

The `/me`, sign-out, and GitHub error responses in this browser run were synthetic. No GitHub OAuth credentials were configured locally, so a real GitHub callback was **not** verified. This browser run also does not prove a real Better Auth cookie lifecycle; P3-02 and P3-09 integration evidence covers real-cookie API behavior. No cookies, OAuth codes, or secret values were recorded.
