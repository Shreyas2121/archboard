## Behavior proved

The authenticated board integration suite now exercises A11 through the shared durable-update permission boundary with real Better Auth cookies. Viewer, nonmember, known cross-board, and random cross-board proposals are rejected; accepted Y.Doc bytes, `latest_seq`, update rows, and receipt rows remain unchanged. Existing HTTP tests compare inaccessible and absent board/subordinate resources and enforce owner/editor/viewer roles.

A27 now observes a PostgreSQL `Lock` wait through `pg_stat_activity` before releasing the competing transaction in each order. An update holding the board row blocks an HTTP archive until it commits. In the reverse order, a manually held archive transaction blocks the graph write, then commits; the graph write is rejected with `BOARD_ARCHIVED` and leaves sequence, rows, receipts, and accepted bytes unchanged. The additional existing pre-transaction barrier test confirms an archive committed before the update lock is rechecked. These are independent database connections, not an in-process mutex.

The existing A19 test uses two Better Auth cookie-derived users and a barrier reached by both transactions before the board lock. Both arrivals while the first transaction is open require independent connections. One user records the invite acceptance and membership, the other receives `INVITE_EXHAUSTED`, and the winner's retry succeeds without a second member. The complete integration suite also covers board creation at the active limit, idempotency same-key races and conflict, stable equal-timestamp pagination, role/remove races, invitation states, and transaction rollback failpoints.
