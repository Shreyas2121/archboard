## Behavior proved

`POST /api/v1/boards` creates an actor-owned blank board, validated schema-1 Yjs snapshot, and replay-safe idempotency result in one transaction. The owner comes only from the Better Auth cookie. A repeated key and canonical request returns the same response; the same key with different content returns 409. A snapshot-insert failure rolls back both the board and idempotency row. Independent concurrent creates at 99 active owned boards result in exactly one hundredth board and one 429 limit response.

`GET /api/v1/boards` lists owned or joined boards without duplicate rows, supports trimmed case-insensitive literal title search and the explicit archived filter, and paginates by `(content_updated_at DESC, id DESC)`. The cursor uses exact PostgreSQL microseconds formatted as strict UTC ISO text before opaque encoding. `GET /api/v1/boards/:id` returns only safe metadata, effective role, decimal-string sequence, owner summary, and member count; unrelated users receive the same 404 category as a missing board. Neither route loads graph bytes or invitation data.

`PATCH /api/v1/boards/:id` checks the shared P3-04 permission service under the board lock. Owner/editor metadata changes increment `metadata_version` once and use database time; viewer and nonmember writes are denied, archived writes conflict, and a stale expected version returns 409 without a partial update. A no-op leaves the version and timestamp unchanged. Metadata changes never advance `latest_seq`.

## Contracts used

The strict shared create, list-query, path, patch, summary/detail, cursor, and error schemas from P3-01; `MAX_ACTIVE_OWNED_BOARDS` and page-size limits; P3-03 transaction/snapshot/idempotency primitives; P3-04 permission decisions; and the P3-02 trusted session actor. List owner, membership, and member-count data are batch-loaded, not queried once per board.

## Database evidence

The HTTP suite creates a process-unique schema, applies the committed foundation migration with synchronization disabled, starts the real Nest/Better Auth handler against that schema, and drops the schema in teardown. It verifies the snapshot row's version, sequence, and exact byte length; the P3-03 snapshot unit/integration suites separately decode and validate the Yjs bytes. A temporary `NOT VALID` snapshot check in the isolated schema rejects only new inserts, proving failed creation leaves neither a board nor a receipt. The 100-board race uses two independent HTTP requests and database connections. Pagination includes equal timestamps, membership joins, a strict cursor, search, archived filtering, and outsider isolation. Stale-version and no-op tests inspect the resulting HTTP metadata and unchanged graph sequence.

Existing indexes support owner/member access and idempotency lookup. Larger mixed-fixture `EXPLAIN (ANALYZE, BUFFERS)` measurements remain part of P3-12; this task does not make an unsupported index-performance claim or edit the historical migration.

## Authentication and security evidence

Each HTTP role obtains an actual Better Auth `HttpOnly` cookie from the mounted handler. Anonymous create is 401; unknown request fields, invalid cursors, and out-of-range limits are 400; nonmember detail/update is 404. Response schemas exclude auth/session/provider fields and raw graph bytes. Unexpected persistence failures return a safe request-ID envelope without SQL or stack traces. The GitHub provider/callback path remains unrun, as recorded in P3-02.
