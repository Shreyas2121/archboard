## Behavior proved

All Phase 3 product routes remain under `/api/v1`; `/api/auth/*` remains mounted directly through Better Auth. Controllers use the same shared Zod request and response schemas. A central API boundary maps validation, authorization, domain, idempotency, parser, and unexpected failures to documented safe envelopes. The filter supplies the same request ID as the `x-request-id` response header. Product JSON bodies and query targets are bounded before application work; oversized input returns 413. Structured logs contain only request ID, route template, status, duration, and available validated actor/board IDs and error code. Token-bearing URLs and request bodies are omitted.

Invitation routes have a bounded per-peer request window and return a safe 429 envelope with `Retry-After` when exceeded. Better Auth's built-in throttle is explicitly enabled in production. `GET /health/live` is process-only. `GET /health/ready` checks the initialized data source, pending TypeORM migrations, and required auth/board tables. Removing the migration record in the isolated integration schema makes readiness return 503 while liveness remains 200. `/api/v1/openapi.json` publishes OpenAPI 3.1 paths, cookie security, parameters, request/response schemas generated from the shared Zod contracts, and documented success/error statuses for all 16 product operations.
