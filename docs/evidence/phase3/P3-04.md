## Behavior proved

`BoardPermissionService` is the single application-level owner/editor/viewer/no-access and archive-state policy. It exposes read, metadata-write, graph-write, and access-management decisions, plus an owner-only lifecycle decision needed for restore. Missing and unrelated boards both return `NOT_FOUND`; known viewers denied writes and editor/viewer access management return `FORBIDDEN`. Existing members may read archived boards; active-only writes return `BOARD_ARCHIVED` once the role permits that operation. Ownership is derived from `boards.owner_user_id`, never a membership row.

Ordinary reads and advisory graph-write preflight use an unlocked lookup. Every authoritative mutation check takes an active transaction, locks the board row, and reads membership in that same transaction. The collaboration durable-update harness now calls this service both before candidate validation and again under its existing write transaction; its copied owner/member/archive query and role policy were removed. The service returns application decisions, not HTTP exceptions; the harness translates denial to its existing durable-update error type at that boundary.

## Contracts used

Shared `BOARD_ROLES` and error codes `NOT_FOUND`, `FORBIDDEN`, and `BOARD_ARCHIVED`; the P3-03 board-row lock and bigint-as-string authority state; the existing commit-before-ACK, receipt, causal-validation, and durable-update failure behavior. The public application port does not import TypeORM. Its PostgreSQL adapter uses TypeORM entities and the existing transaction helper.

## Database evidence

The permission suite migrates a process-unique isolated schema on the direct connection and creates synthetic owner, editor, viewer, and unrelated users. Real PostgreSQL checks cover the active/archived role matrix, missing-versus-inaccessible equivalence, and editor removal between optimistic preflight and locked check. An archive transaction holds the board row on one connection; a concurrent graph permission check on another connection receives PostgreSQL lock timeout `55P03`, then, after archive commits, a fresh locked check returns `BOARD_ARCHIVED`. The durable-update suite uses the shared service through actual persistence: viewer and nonmember denials leave accepted Y.Doc bytes, `latest_seq`, `board_updates`, and `update_receipts` unchanged. Existing archive and role-removal recheck tests still pass. The full regression suite passed all 36 real-database tests.

## Authentication and security evidence

The harness uses synthetic session-token authentication in its focused persistence tests. It authorizes before revealing existing receipts. A nonmember receives `NOT_FOUND` whether the board exists or not; no board metadata or graph bytes are returned. Actual Better Auth cookie HTTP behavior remains covered by the unchanged aggregate integration suite, not by this new permission service test.
