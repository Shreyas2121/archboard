## Behavior proved

Strict Zod schemas now cover safe current-user and user-summary data; board summaries, details, creation, versions, lifecycle requests, members, invites, preview, acceptance, path/query parameters, cursor encoding, and REST envelopes. Contract tests reject unknown keys, invalid roles, malformed UUIDs, bad UTC timestamps, numeric or out-of-range sequence values, malformed cursors, invalid limits, noncanonical invite tokens, and mismatched one-time URL flags. The existing Phase 1 graph/protocol tests remain passing.

## Contracts used

The single existing `BOARD_ROLES` source supplies owner/editor/viewer values; invite/member change roles are its editor/viewer subset. The existing UUID and decimal sequence schemas supply application IDs and PostgreSQL bigint JSON values. Better Auth user IDs remain opaque strings. New shared constants define title/description, owned-board, pagination, invite, and idempotency limits. The cursor encodes a versioned `(timestamp, id)` tuple as canonical base64url; board lists use `contentUpdatedAt`, and clients treat the cursor as opaque. The invite response permits a URL only when `inviteUrlAvailable` is true, including redacted replay shape.
