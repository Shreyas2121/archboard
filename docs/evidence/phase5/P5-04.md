# P5-04 — reopen cached boards offline

Parent: `732bf0170deeeb3c69192d3b13be5fb184e49fcb` (`feat(web): show cached boards offline`). Branch: `phase-5-offline-product`. Commit subject: `feat(web): reopen cached boards offline`.

## Implementation

The direct `/boards/:boardId` route now checks the selected account's cached board record and local document when the session or board-detail request is unavailable. It opens the existing IndexedDB snapshot and ordered local log through `BrowserWriterSession`, which acquires the account/board Web Lock before attaching writable persistence. A missing account, missing cache record, or missing snapshot has an explicit unavailable state. The dashboard links to locally available cached boards and leaves boards without a local document disabled.

`EditorSession` grants commands only after either current server access or route-validated cached access, and only when a local copy or server-ready state exists. Cached viewer and archived boards remain read-only. Reopening an existing local copy does not enqueue a fabricated initial state. When the first tab releases the writer lock, the second tab attaches its sync status to the newly writable binding. Device-save status still comes from the persistence transaction and outbox commit, rather than from shell or graph hydration.

## Served offline browser evidence

URL: `http://127.0.0.1:4173/boards/00000000-0000-4000-8000-000000000041`. The production preview's service worker controlled the page before Chromium entered true offline mode. The tested `dist/index.html` SHA-256 is `4FB3B0D3F9B0026794D8423571EA1A5437BBC17743E22211C16451EE99D33CB6`; `dist/sw.js` SHA-256 is `018AF2DA712826D88373B50F2E91A13A18C92F53D20375F6E5A64639C82BFC11`.

The harness seeded a valid Yjs snapshot and account-scoped metadata in IndexedDB as a synthetic previously cached board. It did not mock the service worker, Web Lock, React network state, persistence writer, or offline browser condition. The editor hydrated the initial node at `{x: 80, y: 120}` and displayed **Offline · cached copy** with zero outbox entries; it did not display a new device-save label from hydration alone. A real UI action created a note and changed its title while offline. The page displayed **Saved on this device · offline** only after the durable local log and outbox entries appeared. The test compared each pending update's exact bytes with its matching local log record. After closing the writer and reopening the direct editor URL offline, it compared the full projected graph, including title and geometry, and the exact pending outbox records. Both matched the committed pre-close state.

A second tab was read-only while the first held the lock, then became writable after lock transfer. Cached viewer and archived boards remained read-only. An unknown board, a metadata-only board without a snapshot, and a board under another account all showed the unavailable state without borrowing graph data. Removing the account marker showed the no-account state. Durable `/demo` namespace record keys remained unchanged across account selection changes.

This is a served browser proof of local edit, commit, lock transfer, and offline reopen on a synthetic prior cache.
