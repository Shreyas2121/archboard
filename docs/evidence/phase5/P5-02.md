## Behavior proved

Successful session identity records only the deployment origin and user ID as a local account marker. A network-unavailable state selects that marker only when there is no pending local sign-out intent. A resolved signed-out or pending session selects no cached account. A later real session selects its exact user. The `/demo` sentinel cannot become an account marker or enter the board cache.

Authenticated board detail fetches write a safe metadata subset under the origin/user/board/schema namespace. Selected-account list and read helpers use only that account's IndexedDB key range. Cache entries expose last metadata fetch time, last local snapshot/log commit time, effective cached role and archive state, and the actual received server sequence from the durable received-state store. A missing snapshot, a gap in the update log, or an initial empty snapshot without committed graph/received state reports unavailable. Cache metadata alone never grants upload authority.

## Contracts used

The marker is a local selector, not a Better Auth session. Pending sign-out is stored separately per origin/user without credentials, so switching users does not erase another user's pending intent. The online REST session and server authorization remain authoritative. Local availability is conservative structural evidence; P5-04 must still validate and hydrate the graph before editing. No graph bytes or owner identity are added to cached metadata.

## Changed scope

`packages/sync-client/src/persistence` account selector, typed board cache, exact namespace prefix, and adapter metadata preservation; focused frontend session and authenticated board-detail integration; native browser tests. Existing IndexedDB stores were reused, so no schema-version change or dependency was needed.

Not applicable to the browser-local cache model. No real authenticated cookie, WebSocket ACK, or PostgreSQL state is claimed here. The frontend records the marker after its existing validated `/me` response; a new end-to-end real-session marker observation remains **UNRUN**.

## Account, security, and recovery evidence

Only user ID and origin are stored in the local account marker, without email, session token, cookie, or graph bytes. Cache summary strips owner identity and server `latestSeq`; the received sequence comes from local durable state. A pending sign-out key prevents reuse even if an authenticated outcome for that same user is presented to the selector. Explicit online sign-out removes the selected marker while leaving account-scoped board data for the later P5-07 preservation flow.
