## Behavior proved

The implementation gives the online and cached/offline dashboards a shared sign-out control. It counts account-scoped boards with pending outbox entries before sign-out and offers Cancel, Retain local copies, and Download recovery followed by explicit clear. The recovery bundle contains each board's validated local graph and exact queued update bytes, IDs, sequence, hash, and initial-state flag. Export failure does not clear any namespace. Clear acquires every affected board's Web Lock, rechecks the pending IDs, and deletes only those exact namespaces. A held lock or changed queue rejects clear before deletion. These IndexedDB and dialog paths await browser execution.

Sign-out records an origin-scoped intent without a credential before clearing authenticated UI/query state or notifying other tabs. Better Auth invalidation is attempted only for the same current user; network failure leaves a visible pending server-invalidation state. Session lookup gates authenticated user data until that intent resolves. Account changes with old pending work require the same preservation choice before selecting the new account. BroadcastChannel and storage handlers are wired to clear other tabs' authenticated state; editor route cleanup is wired to release their sessions and writer locks. Their combined rendered behavior awaits browser execution. Retained records remain under the old account; `/demo` is untouched.

## Contracts used

Only a previously authenticated account marker can select offline boards. The marker is not session authority. IndexedDB outbox entries are grouped by origin/user/board/schema; Better Auth owns server sign-out; Web Locks own exact namespace clearing. TanStack Query holds online metadata only. No graph data is sent over BroadcastChannel.
