# P5-05 — reconcile offline board edits

Parent: `465f33f` (`docs: defer browser verification during implementation`). Branch: `phase-5-offline-product`. Commit subject: `feat(sync-client): reconcile offline board edits`.

## Implementation

The Phase 4 local persistence adapter already reopens the same ordered outbox records, merges full `ready` snapshots as remote Yjs updates without creating outbox entries, and atomically writes the ACK receipt, received sequence, and outbox removal. P5-05 closes a transport race around those operations. A `ready` message now completes its pre-drain work before the client reports readiness or a server-save state. After each asynchronous persistence step, the client checks that the socket still belongs to the current session. Drain checks the socket and send authority again after reading IndexedDB, so a closed connection cannot send an old session's queued update through a new connection. A failed WebSocket send reconnects while preserving the pending record.

The web editor's existing `beforeDrain` callback queues initial board state when needed; its cached-access route starts the same sync client after offline reopen. No whole-board REST save or second outbox was added.
