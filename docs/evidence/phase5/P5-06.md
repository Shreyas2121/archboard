## Behavior proved

The sync client retains denial codes and authoritative archive events. A denied update stops the ordered drain without removing its outbox entry. An owner restore event permits replay of the same pending update ID and bytes; a viewer downgrade and archive event freeze editing. The editor reports separate expired-session, unsupported-schema, and permanent-validation states with recovery export available. A confirmed revocation caches read-only access so a later offline reopen cannot use an old editor role. Reload server version remains an explicit exact-namespace decision and is unavailable during a sync denial or recovery error.

## Contracts used

The account/board/schema namespace, committed local Yjs log and outbox, server receipt, Web Lock, and existing recovery download remain the sources of truth. Cached access only controls local editing. PostgreSQL and the authenticated socket decide whether a queued update commits. No pending update is copied to another account or board.
