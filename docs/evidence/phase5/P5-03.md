# P5-03 — cached-only offline dashboard

Parent: `0becdfd07a66070f8f583f0fa794066a7e14f392` (`feat(sync-client): add account scoped board cache`). Branch: `phase-5-offline-product`. Commit subject: `feat(web): show cached boards offline`.

## Implementation

`/boards` now shows a cached-only dashboard when the session check or board-list request cannot reach the server (network failure or HTTP 5xx). A prior account marker is required for uncertain sessions. The list comes from `listSelectedCachedBoards`, so it is limited to that deployment, selected account, and current schema. Online board listing still uses the existing TanStack Query path. A definitive signed-out session does not select a cache.

Each cached card shows cache time, last local document save time when present, role, archive state, and whether a local document is available. The page states that the subset and metadata may be incomplete or stale. Search and archive filtering use the local subset only. Create, details editing, archive/restore, duplicate, and opening are disabled in this task; the banner explains which server actions need reconnection, including access and invites. Cached editor opening belongs to P5-04. Missing metadata, missing document, first-use empty cache, local cache read failure, and offline with no selected account have separate accessible text and retry or demo paths.

Synthetic secure API and WebSocket origins were compiled into the production bundle. `dist/index.html` SHA-256: `1148277ABF6381717DE2AA0704F5B1915FCA5CBDD95717972FD3CEEC3D5C0E55`; `dist/sw.js` SHA-256: `510391BF81C1131DDAABD610623D98CA56DB993DA9161355BBFFDDEEF01B1C86`. A production preview installed and controlled the worker before Chromium's true offline mode. A direct offline `/boards` navigation rendered the cached dashboard. The browser harness seeded only synthetic IndexedDB cache records and a prior account marker; it did not mock the worker or React's network state. Account A showed its active cached records, including unavailable document and missing metadata states. Account B and `/demo` records were absent. Search, archive filtering, stale-details labels, and disabled server actions passed. Switching to account B showed only its record. Removing the marker showed the no-account offline state; a new account marker with no records showed the first-use empty state. Cache Storage held 134 static request entries and no API or auth paths.

This proves dashboard rendering and account-scoped cache selection under a real offline browser. It does not assert a real Better Auth session, server response, database mutation, or offline editor hydration. P5-04 owns opening cached documents.
