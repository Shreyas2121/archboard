## Behavior proved

The generated worker imports and precaches a compatibility responder reporting graph schema 1, sync IndexedDB schema 2, and open app window count. The app registers without automatic activation, detects a waiting worker, and offers Later or Review update. Review reads pending outbox IDs in the selected account namespace, verifies the waiting worker's graph and database schema, and offers recovery download. A compatible update with pending work requires the user to choose Retain changes and update. Unknown or incompatible worker metadata, another open app tab, or unsupported local pending schema blocks activation. No update action clears a board namespace.

Before activation the app freezes local commands in each active editor, stops its socket, waits for queued socket/receipt work and local IndexedDB writes, checks local save status, and rechecks exact pending namespaces and update IDs plus worker compatibility. Cancellation or a failed pre-activation check resumes the old editor and socket. The worker receives `SKIP_WAITING` only after those checks and the user's update action. On `controllerchange`, active editor sessions close before reload. The existing schema-unsupported sync state remains read-only with recovery; the update prompt can download recovery for supported local schemas even when the waiting worker is incompatible. Workbox precache cleanup operates on static Cache Storage; this implementation has no worker IndexedDB access or cache-clearing path.

These are code and build observations, not a served-browser handoff proof.

## Contracts used

`GRAPH_SCHEMA_VERSION`, `SYNC_DATABASE_VERSION`, selected local account marker, account-scoped outbox enumeration, exact update IDs, editor `whenIdle`, and P5-07 recovery export. The compatibility responder's literals are checked against the shared package constants by the non-browser test. An unknown responder fails closed. `/demo` stays under its local namespace and is only quiesced if it is the active editor.
