## Behavior proved

The editor now has a keyboard-accessible Local storage dialog for the current board namespace. It shows whether a usable local copy is present, when board metadata and the snapshot were cached, the exact pending outbox count at the last check, current local write status, and browser-reported usage/quota when available. It labels browser storage as best effort rather than a backup and distinguishes local commits from server acknowledgements. The dialog reads only one origin/user/board/schema namespace and does not load outbox or local update logs for this diagnostic view.

Storage-error and unsupported Web Lock states show an in-memory recovery action beside the status message. A storage error keeps editing paused and no saved label is shown for uncommitted work. Recovery download validates the current graph through the existing recovery serializer; export failure is announced without clearing local data. Quota errors receive a bounded, non-sensitive diagnostic; other IndexedDB failures retain the generic recovery message. The offline editor and cached dashboard now say when a missing local document may have been cleared or evicted, and require authenticated reconnection to fetch it again.

These are implementation, build, and non-browser state observations. A rendered edit with an injected failure is not yet proved.

## Contracts used

The sync client's local persistence phase governs editability and save labels. A device save requires an IndexedDB commit; the dialog's pending count is an exact-namespace outbox index count, not a server receipt. `navigator.storage.estimate()` is treated as an optional, origin-wide estimate. An offline shell that the browser cannot load cannot render Archboard's unavailable state, so no successful offline opening is claimed in that case.

## Changed scope

Focused editor storage dialog and status copy; exact-namespace sync-client health read and safe quota diagnostic; cached board/unavailable copy; non-browser storage-state script and deferred browser namespace test. No API, migration, or service-worker cache policy changed.
