## Delivered

The [central enforcement map](../../phase-8-admission-validation.md) records actual
frame/base64/decoded/request/candidate limits, pinned causal validation, worker
ceilings, room/fanout bounds, transactional resource caps and export allocation
guards. It also specifies compatible account+board/board abuse budgets, bounded
identity retention, retry semantics and prepared A23/A30 socket/race assertions.

Gateway fragmentation is bounded before concatenation or parsing. Authenticated
pre-hello sockets, pending upgrade operations, unresolved timed-out auth lookups
and room FIFO work now have finite ceilings. Worker options cannot raise the
published two-worker/two-second/twenty-waiter policy. Existing isolated candidate
validation and commit-before-install/ACK remain unchanged. Hidden text and complete
encoded-state negatives prove validation does not rely on visible projection alone.

Traffic uses server monotonic time with independent content/presence/presenter
lanes. Aggregate account+board and board credit survives reconnects; identity-map
capacity fails safely instead of evicting spent credit. Presenter queue refusal
returns temporary `SERVER_BUSY` without clearing a valid lease or closing peers;
actual unavailable authority still fails closed. Operational rates/admission/timing
alias the shared constants.

Sync transport preserves exact FIFO IDs/bytes on temporary failure, increases
backoff across repeated READY-then-refusal cycles, and resets after saved progress
or empty READY. Oversized local pending bytes enter `DOCUMENT_LIMIT` recovery before
base64 allocation; the existing complete pending-work export remains available.
No graph, text, history, receipt or dependent pending update is discarded.

Existing locked board/checkpoint/thread/comment cap implementations and race tests
are retained. The durable invalid/causal regression now prepares an explicit next
legitimate commit at sequence one after rejected work creates no logs/receipts.
No database case was executed.
