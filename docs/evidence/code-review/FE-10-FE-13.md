# FE-10 through FE-13 fixes

Date: 2026-09-30. Scope: FE-10, FE-11, FE-12, and FE-13 in `review-code.md`.

## FE-10: shortcut ownership

The command hook owns graph keyboard shortcuts. It checks explicit editor modal
state, pending deletion confirmation, mounted dialogs (including auth/update
dialogs), editable targets, `defaultPrevented`, and IME composition before acting.
Dialog buttons and temporarily background-focused targets cannot trigger graph
commands. The canvas no longer handles Escape independently: an accepted editor
Escape dispatches a gesture cancellation event and clears selection centrally.
Dialog Escape remains available to the existing dialog primitive.

Node tests cover the shared ownership policy for help, reset, deletion, storage,
and server reload dialogs, explicit ownership before content mounts, handled
events, composition, editable/dialog descendants, and ordinary canvas targets
after modal closure. Actual focus, Radix Escape behavior, and shortcut interaction
with React Flow are **UNRUN (deferred by user)**.

## FE-11: projection and rendering reuse

Writer snapshots expose a document generation. Yjs transactions with changed
types advance it before persistence status notifications; document replacement
also advances it. Writer projection reads and editor session refreshes reuse the
same projection until that generation changes. Update notifications cover remote
changes to read-only views as well as writable documents. Both document listeners
are removed during view cleanup, and closing clears the projection cache.

Final card and boundary rendering objects are cached by their source entity,
selection, editability, and resize handlers. Unchanged nodes retain their data
objects. Resize completion reads the latest projection through a ref, keeping its
handler stable across unrelated graph edits. Removed rendering entries are evicted.
These caches contain derived rendering data; Y.Doc remains the editable authority.

Geometry, deletion, creation, and alignment prevalidation reuse one physical graph
read. Alignment reuses its read when invoking geometry validation. Schema, capacity,
live-entity, duplicate-ID, and atomic transaction checks remain in place. The helper
for composing geometry commands with an existing physical read is excluded from
the document-model public barrel.

Instrumentation verifies one projection export across 500 status notifications,
invalidation after text edits/document replacement and remote read-only updates,
session projection identity across status/access updates, unchanged final rendering
references after editing one card on the limit fixture, and one physical read for
geometry/alignment/deletion. Existing atomic invalid-command tests also pass.

## FE-12: React Hooks lint

Exactly pinned `eslint-plugin-react-hooks@7.1.1` enables `rules-of-hooks` and
`exhaustive-deps` for `apps/web/src/**/*.{ts,tsx}`. The installed plugin declares
compatibility with the workspace's ESLint 10 version. See the
[official Hooks lint documentation](https://react.dev/reference/eslint-plugin-react-hooks).

Existing findings were corrected semantically: clipboard cleanup explicitly follows
session changes; text access preserves target identity by entity/ID/field and follows
binding generation; subscription cleanup includes its owning session; geometry
draft synchronization depends on stable coordinate values rather than entity objects.
No rule suppressions were added.

Node ESLint fixtures confirm errors for conditional hooks and omitted reactive
dependencies, and confirm a corrected fixture passes.

## FE-13: responsibility splits

The shell composes `EditorToolbar`, `EditorInspector`, and `EditorDialogs`. Status
precedence/editability policy, palette definitions, and composition contracts live
in non-component modules. Inspector selection derivation belongs to its composition.
Session mutations and reset/reload/recovery orchestration remain together in the
shell/session; dialog control state, pending guards, object keys, and focus-return
refs retain their owners.

Auth transition state, epoch guards, cross-tab listeners, and sign-out live in
`auth-transition-coordinator.ts`. QueryClient/key/constants/contracts and current-user
query options are separate modules. `session-query.tsx` retains the hooks and dialog
composition with compatible public exports. Its pending-switch hook uses one
external-store subscription in place of its previous event subscription.

The extraction adds no React subscriptions or graph state. The theme subscription
moved into the toolbar. Node tests verify status precedence/editability, stale auth
responses after sign-out, pending-switch subscription cleanup, and boundary listener
cleanup/private-cache clearing. Actual dialog focus and browser account flows are
**UNRUN (deferred by user)**.
