# FE-03, FE-04, and FE-05 fixes

Date: 2026-09-30. Scope: the three findings in `review-code.md`.

## FE-03: unconditional writer resource cleanup

The writer owns its document and persistence adapter before initialization awaits,
so partial views have an explicit cleanup owner. Initialization and transition
failures dispose resources immediately while preserving the original operation
error. Reset/deletion operations participate in the tracked transition boundary;
close waits for that work and prevents subsequent reopening.

View cleanup detaches the subscription and closes persistence before destroying
the document, attempting every step even if an earlier one rejects. Session
disposal likewise attempts lock release, hint-channel teardown, lifecycle listener
removal, and final closed notification despite cleanup failures. Disposal and close
are idempotent. Background hint/pagehide operations and route cleanup explicitly
report rejected promises. Editor teardown waits for opening to settle and continues
through failures in sync, subscription, undo, and writer cleanup.

Node tests inject document-factory failure, persistence initialization failure plus
close failure, reset deletion failure, replacement initialization failure, seed
failure, and view-close failure. They verify lock release, exactly-once cleanup,
subsequent lock acquisition, close during an owned deletion, and handled pagehide
rejection. Editor tests also verify writer cleanup after a sync-stop failure and
handled route-boundary cleanup rejection. Native Web Locks/IndexedDB behavior is
not established by these controlled adapter tests.

## FE-04: reactive text binding availability

The editor exposes a text-binding generation driven by writable document identity
and effective edit permission. Status-only notifications leave this generation
unchanged. Product text fields subscribe to the generation and re-resolve access
when it or their target changes. The binding effect removes the previous observer,
resets draft/error/composition state, and loads the active document's value.

Node tests exercise viewer-to-editor promotion, permission loss, secondary-tab
writer takeover, document replacement, active-document editing, old-observer
unsubscription, and generation stability for status-only notifications. These
tests cover session/binding contracts; actual mounted React field behavior remains
deferred for browser verification.

## FE-05: target-owned inspector drafts and URL concurrency

Card, edge, and boundary inspectors are keyed by entity ID in the shell, so target
switches remount their transient fields. Edge/boundary inspectors use product text
fields; those now also reset composition state on binding/target changes.

URL fields commit only a dirty, normalized value that differs from its initial
baseline while editing is allowed. A synchronous dirty ref prevents an Enter
commit followed by blur from writing twice. If a peer changes the URL during a
dirty draft, the command compares the expected baseline with the current Y.Doc
value before mutation and rejects the stale draft. Escape discards it and loads
the current value. An untouched field cannot write back an older URL on blur.

A Node command regression verifies rejection without overwriting the peer's URL
and a successful commit after accepting the latest baseline. Keyed inspector
ownership and untouched/Enter/blur guards were reviewed in source; mounted field
switching and event ordering remain deferred for browser verification.
