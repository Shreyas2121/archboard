# FE-06 through FE-09 fixes

Date: 2026-09-30. Scope: FE-06, FE-07, FE-08, and FE-09 in `review-code.md`.

## FE-06: canvas gesture reconciliation

The canvas tracks active drag/resize object IDs. Projection updates merge document
data and all unaffected geometry while retaining temporary geometry only for active
objects. Deleted objects disappear immediately and leave the active set. Card and
boundary resizers explicitly begin their gestures.

Completion clears gesture ownership and reconciles regardless of command outcome.
The geometry callback returns the committed document projection on success or null
on rejection/unavailability. Successful normalized geometry is rendered directly
from that projection; rejected temporary geometry is restored from the latest
projection. Permission loss, Escape, window blur, and pointer/touch cancellation
clear gestures. Late gesture updates/completions cannot commit after cancellation
or editing becomes unavailable.

Node tests cover remote deletion during drag, remote geometry changes to an
unaffected object, temporary resize preservation, rejected-commit restoration,
and cancellation/late completion after permission loss. These test the gesture
state/reconciliation adapter; actual React Flow event ordering remains deferred.

## FE-07: focused outbox and receipt reads

Local persistence now exposes a namespace-index count, a one-record oldest-first
lookup using `byNamespaceAndSequence`, and a receipt lookup by the compound primary
key `[namespace, updateId]`. Ordered sync uses these APIs for drain, refresh, and
unexpected ACKs. Bulk export/recovery APIs remain available. Existing atomic
log/outbox and receipt writes are unchanged.

A controlled database test drains a synthetic 1,000-entry backlog: count paths
perform no payload reads, selected-record queries request one entry, and payload
reads grow linearly with delivered entries. A transport test sends 128 exact
payloads in FIFO order without bulk reads, accepts a matching duplicate ACK using
direct receipt lookup, and reconnects for a mismatched duplicate ACK sequence.
Native IndexedDB query/transaction and crash/retry tests remain deferred.

## FE-08: preserve outage classification

API requests read response text separately from JSON parsing. Non-success statuses
remain HTTP failures when their body is HTML, empty, or malformed JSON. Successful
body-read failures are transport failures, while malformed successful JSON remains
an invalid response. Explicit 401 behavior and contract-envelope error handling
are retained; aborted requests preserve their cancellation error. Dashboard and
editor-route fallback decisions share `serverUnavailable`.

Node fetch tests cover HTML 503, empty 502, malformed JSON 200, 401 notification,
successful-response body interruption, and abort during body reading. Route-loader
tests also verify cache fallback for an HTTP outage without denying board access.

## FE-09: cancellable route loading and stable sessions

The route uses an extracted loading hook and feature-owned loader. Session lifetime
depends on board ID, account ID, and read-only policy, plus an explicit retry or
disabled auth boundary. Profile object/error identity does not recreate the session.
Online/offline transitions reload authority/cache metadata using the existing session.

The loader owns one outer error boundary for construction, opening, configuration,
and cache failures. Each metadata operation has an AbortController and generation
token. Navigation, account/policy changes, or superseding loads cancel requests and
fence late results. `readBoard` forwards the cancellation signal to the API adapter.
Failed sessions are closed, and cached access is checked against the selected account
before and after its asynchronous read.

Node tests cover constructor failure, navigation during a delayed board read,
online/offline session reuse, superseded metadata reads, HTTP outage cache fallback,
and cache failure cleanup. Mounted routing/profile-update behavior remains deferred;
the hook's scalar session-identity dependencies were reviewed in source.
