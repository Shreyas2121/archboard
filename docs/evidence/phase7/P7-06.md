## Contracts used

`@archboard/export` is a pure contracts-only package. Synchronous capture clones and
validates a complete envelope supplied from the local projection and matching metadata.
The caller must supply durable ACK coverage of that exact view. Offline, nonauthoritative,
unacknowledged, pending-persistence and pending-outbox captures are `local-only`.
These helpers do not mutate documents, drain outboxes, acknowledge changes, fetch URLs,
or execute text. P7-08 will connect the helpers to actual file/recovery UI.

The file parser enforces 5 MiB UTF-8 bytes, fatal decoding, nesting at most 32, prohibited
prototype keys, and the existing strict portable envelope/graph schemas. It returns Zod
field/path failures for invalid metadata, versions, IDs, geometry, handles, URLs, counts,
text, endpoints and highlights. Live CRDT validation remains independently tolerant.
Recovery serialization retains complete content above the import cap and returns
`reimportable: false`; no image scope is applied and no content is truncated.

`createFreshGraphUpdate` validates, remaps all entity IDs/endpoints/highlights, validates
the mapped projection, hydrates a new Y.Doc with empty tombstones, validates it, encodes
it and releases it. Committed duplicate reconstruction uses the same helper in the
existing bounded validation worker. Source CRDT bytes/history are never cloned as the
new board's history.

## Schema and API impact

Added authenticated `POST /api/v1/boards/import`, strict `ImportBoardRequest` and
`ImportBoardResponse` OpenAPI components, and UUID `Idempotency-Key` handling.
The response uses the existing board summary envelope. Imported title comes from the
request; description comes from validated portable metadata. Imported time/sync labels
do not set ownership, authoritative timestamps, sequence or durability.

HTTP parsing permits the shared 5 MiB plus 64 KiB request overhead for import, validates
UTF-8/nesting/prototype keys before ordinary JSON parsing, and retains the existing
64 KiB limit for other product requests. The server independently checks the compact
serialized file envelope against the file cap before persistence.

Blank, imported and duplicated boards share the transaction-scoped private initializer:
owner lock/cap, metadata, initial snapshot at sequence zero, and derived owner response.
The existing actor/operation-scoped 24-hour receipt commits with those effects. Duplicate
authorization runs before receipt lookup on every request, preserving owner-before-board
lock order; successful retries do not recapture advanced content. Archived readers may
duplicate; removed readers cannot disclose a stored duplicate result. The initializer
and fresh-graph helper are available to P7-07/P7-10.

No migration or configured database operation was needed or executed. Existing server
timestamps, owner derivation, transactional receipt storage and source locks are reused.
