## Behavior and authority

Each collaboration room owns one ephemeral lease keyed to the server-generated connection ID.
The room queue serializes acquisition, release, heartbeat expiry, committed-step reconciliation,
access notifications and protected fanout. Reacquisition by the same connection preserves its
deadline and selected step; another connection, including another tab of the same user, cannot
acquire, select or release that lease. Step selection reads the committed room projection;
pending-only, missing and tombstoned IDs receive safe denial. Committed deletion clears only the
active step. Neither lease controls nor heartbeat observations mutate Yjs or durable state.

Controls and holder validity use current bounded session lookup and the existing locked
`BoardPermissionService.editGraph` decision: owner/editor on an active board. Each recipient
requires current locked read permission and session validity before delivery. The existing board
authority transaction holds the access lock through fanout. Removed readers receive no presenter
payload. Authority failures close affected sockets and clear authority. Disconnect, session loss,
role downgrade, removal, archive and shutdown release the holder; new/reloaded rooms start empty.

The 30-second lease deadline has its own timer, independent of the 45-second dead-socket bound.
Only a valid holder's native `pong` renews it. Other peers, graph edits, control requests and
same-holder reacquisition cannot renew it. The pinned ws implementation enables automatic pong
by default (`lib/websocket.js`, `autoPong` initialization and receiver ping handler); prepared
real tests disable it for the holder while another peer remains responsive. No heartbeat DTO,
parallel socket, lease persistence, protocol version change or dependency is introduced.

Initial state is queued after authenticated ready activation and buffered graph deliveries.
Joining peers get the current lease, never a pre-ready presenter frame. Graph update deliveries
precede the resulting deleted-step state. Changed lease states fan out; unchanged controls send
current state only to their source. Unrelated graph updates and nonholder disconnects do not
emit redundant presenter frames. Controls reuse the existing presence rate bound in an independent
transient window and the shared frame/size/backpressure protections, without consuming durable
update budget or creating ACKs, receipts, sequences, outbox entries or content timestamps.

## Contract and transport

Version 1 activates exactly the payloads in phase7 section 7.1: empty acquire/release objects,
`stepId` selection, and server `connectionId/stepId/expiresAt` nullable state. Strict schemas
reject extra identity/authority fields, malformed IDs and inconsistent cleared states. The old
reserved-name exports remain compatibility aliases. No database schema or migration changes.

The central `PRESENTER_DENIED` safe error covers contention, nonholder/invalid-step and transient
burst denial. This targeted addition is required because ordinary `FORBIDDEN` and retryable errors
suspend/reconnect the durable stream in the existing client. Presenter denial is observed solely
through the transient surface; current access/session errors retain their existing semantics.

`OrderedSyncClient.presenter` exposes subscription, current state/connection identity, denial,
acquire/select/release, and reset without React, persistence or follow preference. It gates sends
on ready/writable/active access, ignores stale socket events, and clears on stop, disconnect,
protocol recovery, removal and archive. Archive resets observation while retaining the open
connection identity, allowing unarchive to resume controls. A viewer loses local holder state
but remains able to observe an authorized presenter. No UI follows automatically; P7-05 owns
explicit follow and viewport behavior.
