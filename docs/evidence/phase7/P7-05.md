## Behavior implemented

The editor exposes current presenter availability, explicit Acquire presenter and Release
presenter controls for eligible live writers, and Follow presenter / Unfollow for authorized
readers. Lease ownership is displayed only after the server frame grants it. Entering local
presentation or receiving a presenter frame never opts in. Viewers/narrow read-only writers
cannot acquire/broadcast; readers can follow. Demo/local-only, offline, archived, disconnected
and access/session failure states expose local playback without an invented active presenter.

The holder can explicitly broadcast the current step and subsequent Previous/Next/local step
choices broadcast through the existing P7-04 transient transport. Broadcast requires live
editing authority and no pending graph outbox/local persistence writes. Pending/unavailable
steps cannot be sent by the UI gate; final committed-step authority remains on the server.
No automatic acquisition, ownership transfer or retry is added.

Following uses only a valid, live, explicitly opted-in lease and a matching current projected
step. Its rectangle/highlights/notes reuse P7-03 playback and the existing canvas render model.
A null/unavailable/deleted step shows waiting/unavailable status without selecting a substitute.
The current projection can later supply the requested ID; heartbeat-only frames do not refit.
Local presentation remains available when live capability is unavailable.

User pan/zoom movement immediately revokes follow. React Flow's user-event callback is separate
from programmatic fits, so applying a followed viewport cannot itself unfollow. Explicit
Unfollow, presentation exit, lease clearing/expiry, new holder and reconnect also revoke opt-in.
The last valid followed step becomes local navigation when possible, without a camera movement.
Local camera ownership blocks subsequent remote-fit/resize callbacks until an explicit local
step choice or fresh follow action. Later presenter step messages cannot move that local view.
Next/Previous and their arrow shortcuts remain disabled while following; Unfollow restores local
navigation. Named native Button actions are keyboard accessible; Escape exits through the
existing native text/composition/modal shortcut policy. Exit retains launcher focus behavior and
releases an owned lease; pending focus frames cancel on re-entry/session change.

## Lifecycle and state ownership

The per-editor follow controller binds the full storage namespace and current observer
connection. Session replacement gets a new controller, and local playback IDs are tagged with
that controller, preventing a render from fitting a previous board/account's step. Transport
callbacks carry their captured namespace/connection identity and ignore stale bindings. Existing
OrderedSyncClient socket-generation checks remain the first stale-frame boundary.

Disconnect/archive/access failure clears live observation and opt-in. A clear frame, another
holder, expiry, or the same holder returning after its old deadline requires fresh opt-in. A
local expiry timer works even without a clear frame; render and step resolution also reject an
elapsed deadline. Reconnect never reinstates follow or reacquires. Subscriptions, expiry timers,
resize observers, keyboard listeners and focus frames clean up. Leaving the mounted live editor
attempts holder release; the server's disconnect/expiry rules remain authoritative.

EditorSession exposes its existing transport presenter surface. Follow/playback state consists
of hook-local IDs, authority observations and explicit UI intent; no editable graph array or
viewport preference is persisted. Controls use existing Button/Tailwind tokens, plain text and
the public shared-package APIs. There are no dependencies, custom styles, remote fonts, shared
viewport writes, document commands, undo entries or outbox entries introduced by following.
