## Implemented behavior

- Editor toolbar provides full local JSON, checkpoint list/create, and explicit
  committed-source duplication. Lists show name, creator, time and decimal captured
  sequence, support stable pagination, and disable capture at the 100-checkpoint cap.
  Creation rechecks current actor/metadata and actual session durability: settled
  persistence, acknowledged outbox, online ready sync, current owner/editor, active board.
- `/boards/$boardId/checkpoints/$checkpointId` reads an immutable graph, renders the
  existing canvas read-only, and offers a validated title for restore as a new private
  board through the canonical checkpoint `/duplicate` endpoint. It creates no source
  editor session, socket, writable document binding, or source-board command. Fresh
  authorized detail is required to render; offline inspection is unavailable. There is
  no optional persistent snapshot cache or unlabelled stale-detail fallback.
- Dashboard import checks UTF-8, byte/depth/prototype bounds and the shared strict
  versioned envelope/graph before any POST. Preview renders complete content as text,
  never code or remote URLs. Validation/network/cap failures preserve input and preview.
  Import and restore navigate only after a validated current-actor private-board result
  whose ID differs from the source; the server remains the authority for creation.
- Requests freeze body JSON and the original UUID key. Network, unreadable/invalid success,
  server failures, and late generation results remain uncertain. Retry uses identical body
  and key, after actor authentication, inside the conservative 24-hour lifetime. Even a
  later forbidden response cannot establish that an earlier uncertain creation failed.
  No reconnect/focus handler submits a mutation. A definitive sequence conflict refreshes
  committed metadata/list but retains the rejected intent; explicit review/new submission
  selects a new sequence and key. Expired uncertain requests require result inspection and
  deliberate new submission, with a duplicate warning. Frozen context remains in memory;
  the UI exposes exact key/body and warns that reload loses it.
- Existing dashboard create/duplicate also use frozen request handling. Duplicate requires
  an explicit choice to copy committed server content, with a source-board link to wait
  for acknowledgment or download pending local JSON and import it. It never implies local
  pending work was copied by the server.
- JSON captures the full current local projection synchronously, without writes, draining,
  discarding or acknowledging outbox entries. Server-saved requires established durable ACK
  coverage and settled local persistence; offline/demo/recovery/storage failure/access-ended
  states use local-only. Recovery downloads now use the same importable version 1 envelope.
  Files above 5 MiB remain complete and warn that unchanged reimport is unavailable.
  Object URLs are released on success/failure. Fixed filenames do not use board titles as paths.
- Account/board keyed controls, scoped query keys, canceled reads, generation/actor checks,
  and aborted creation on unmount prevent late replies from populating another scope or
  navigating it. Existing local graph/namespace preservation stays intact. Focus/online
  recovery authenticates the actor before invalidating protected reads independently of
  socket connectivity; existing post-commit checkpoint hints refresh the same query prefix.
  `apiRequest` uses HTTP `no-store`; PWA API navigation exclusions and empty runtime caching
  remain in place. Portability dialogs also block editor/presentation shortcuts.
- Board detail is converted to the exact summary shape before caching: `memberCount` no
  longer makes the strict summary cache reject it. Online/cached descriptions pass through
  the loader to recovery exports. Account recovery bundles retain their existing outer
  format and queued bytes; their nested graph recovery now uses the portable envelope.
