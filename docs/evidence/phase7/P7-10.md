## Behavior proved and contracts used

All three fixed templates validate through `portableGraphProjectionSchema`. Registry
resolution validates the ID before lookup and returns a separate validated graph.
Unknown IDs, including paths and prototype-related names, fail without loading code.
The server independently validates the complete creation request before persistence.

Node geometry is separated and highlighted cards fit inside their step rectangles.
The web request-validation rectangle now includes its payload card. Identity sits
above the gateway/application request path; the ownership note sits outside the
application boundary. Geometry checks do not establish rendered text/edge legibility.

Fresh template creation calls the same `createFreshGraphUpdate` and
`initializePrivateBoard` path as import/duplicate/restore. Two instantiations of
each template have mutually disjoint node/edge/boundary/step IDs, valid endpoints
and highlights, preserved content/geometry/style/step order, new Yjs identities
and empty tombstones. Tests compare semantics independently of UUID-sorted
projection array order; the initial positional test assertions were corrected.

No-template requests retain blank creation and its empty-snapshot initializer.
The prepared real HTTP test checks zero nodes, edges, boundaries and steps.
Template selection is included in the normalized receipt request, so changing it
with the same key conflicts rather than replaying different starting content.
The existing owner lock, board cap, derived ownership, snapshot transaction,
24-hour receipt and uncertain-retry behavior remain the creation authority.
