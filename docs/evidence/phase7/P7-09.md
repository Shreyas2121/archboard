## Implemented behavior

- `packages/export` renders a schema-validated, cloned graph projection using fixed
  SVG primitives. It renders component category/technology/description/inert URL,
  code language/body, schema/note text, named boundaries, edge labels/protocols,
  fixed handle endpoints, solid/dashed lines and forward/bidirectional markers.
  Layer order is boundaries, edges, cards, labels. It uses fixed light/dark colors
  and system monospace with explicit character-cell widths; text wrapping can differ
  from the editor. It captures no editor DOM, comments, cursors, inspector, selection
  handles or presentation overlays.
- XML text is escaped. XML 1.0-invalid controls, lone surrogates and U+FFFE/U+FFFF
  become U+FFFD in image display; valid supplementary characters remain supported.
  Complete original text stays in JSON. No raw markup, scripts, event attributes,
  foreignObject, arbitrary CSS, executable links, hrefs, fonts or image resources
  are accepted. Marker and clip IDs are generated by the renderer. External URLs
  are plain text and the existing HTTP(S)-only contract rejects unsafe schemes.
- Body layout scans only a bounded visible character/line budget, including CR-heavy
  inputs. Long bodies are clipped to the card viewport and overflow is indicated.
  Document bounds include labels, stroke/markers and padding, with negative world
  positions supported. Entire diagram and current selection are available; selected
  edges include their live endpoints, internal edges are included, and boundaries
  do not implicitly include contained cards. Missing endpoint edges are counted;
  empty/deleted selections give actionable feedback.
- The editor captures one coherent local projection/selection/theme synchronously
  before awaiting browser work. It does not command the graph, touch Y.Doc or drain,
  discard or acknowledge the outbox. Demo and board sessions can export local pending
  edits. Account-marker/sign-out checks fence the final download, and scoped controls
  abort work on unmount or dialog close. Image dialogs block editor/presentation
  shortcuts. Controls reuse the existing accessible dialog/select/button primitives.
- Controlled SVG objects are immutable and registered by renderer identity; the
  browser adapter rejects arbitrary/copied SVG input. SVG geometry and PNG output
  require finite positive dimensions, at most 8,192 pixels on either side and
  32,000,000 total pixels. PNG uses exactly 1× or 2×. Limits are checked before
  Image/canvas allocation. Excess output asks for scope/scale reduction without
  silently cropping or shrinking. Filenames use a bounded sanitized title and fixed
  format extension.
- PNG uses a fresh transparent canvas and draws only controlled SVG; background is
  supplied by SVG when enabled. Preparing/downloading/error states, cancel, explicit
  retry and SVG/JSON alternatives are exposed. Decode/encode operations have a
  30-second deadline. Object URLs, image handlers/source, timers/listeners and canvas
  dimensions are cleared on success, failure, abort and timeout. Late encoding
  callbacks cannot download. Temporary blobs become unreachable after the operation;
  cancellation cannot synchronously stop the browser's internal encoding operation.
  Existing CSP permits blob image decoding and PWA has no runtime API caching;
  neither policy was weakened.
