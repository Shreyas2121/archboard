## Behavior proved and changed scope

The registered `pnpm phase7:verify` has explicit full, `--non-browser` and
`--implementation` modes. Its fixed manifest separates Node/static/build children,
real PostgreSQL/session/socket/schema children, native/served browsers and three
required missing human/integrated evidence rows. Unknown or combined modes reject.
Failed children propagate; independent checks continue; a failed build leaves
dependent checks UNRUN instead of reusing stale artifacts. Zero/missing test
counts, skipped/cancelled/TODO tests, process errors and pending configured
migrations cannot pass. Partial-mode success cannot close the full gate. Default
full mode fails closed on the currently unwired required evidence rows.

The runner captures bounded child output only in memory and persists fixed-label
numeric summaries, commands/cwd and durations. It scans its report for secrets.
Implementation mode does not load DB env files or pass DB/auth-secret variables
to children. Scanners may compare local secret values without issuing requests
or printing matches. No protected payload, cookie, token, connection string,
browser state, trace or raw failing log is committed.

New `normalizeGraphFixtureIds` is a test-fixture comparison helper in the pure
fixtures package. It strictly validates, assigns canonical IDs independently of
UUID-sorted array order, remaps endpoints/highlights and retains every authored
field. It rejects ambiguous identical fixture entities rather than guessing an
isomorphism. It does not change production creation/remapping or live documents.
Model tests cover all-kind, typical and three template copies with complete
semantic equivalence, fresh IDs/empty tombstones and detectable corruption.
Prepared stored import/duplicate/restore/template tests reuse this same helper.

Prepared raw HTTP A18 cases cover wrong version, forged ownership/credentials,
self-loop, invalid handle/highlight/URL and prototype keys, requiring whole
rejection with no board/receipt. Duplicate retry now advances an actual committed
Yjs update/log plus sequence instead of temporarily changing sequence metadata
alone. Its prepared snapshot-failure rollback now requires no board/receipt and
a successful exact-key retry after removal of the failpoint.

New served P7-11 harness wires all-kind actual file import/download and inert
hostile text, exact-key capture retry, read-only direct checkpoint route,
independent original offline pending work, fresh restored board and subsequent
original/restored edits, immutable checkpoint content, active-worker API cache
exclusion and offline unavailability. Existing A21 now waits for an active worker
before offline reconnect assertions. Browser execution remains deferred.

Owned changes: root script/README registration; verifier manifest/runner and its
11 Node tests; evidence scanner; fixtures helper/export; six model comparison
tests; prepared board integration regressions and served harnesses; run/coverage
guide and this evidence/report. No dependency upgrade, schema, migration, API
route, request/response contract or authorization change.
