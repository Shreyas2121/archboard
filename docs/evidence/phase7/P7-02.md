## Behavior proved

Step creation captures supplied world rectangles and live node/edge highlights in one
fully initialized transaction. Property edits change only supplied fields; title/notes
preserve unchanged Y.Text items with a bounded prefix/suffix splice. Interactive text
edits continue through the existing incremental `editGraphText` command.

Strict partial/reorder inputs reject unknown/immutable fields before mutation. New or
explicitly changed highlights require unique live targets of the correct kind, including
live edge endpoints. An unrelated edit remains available when an existing target has
been deleted concurrently. Full shared text/order/rectangle/count/reference bounds apply.
Reorder validates the entire bounded input before one transaction and sorts by `(order,id)`.

Projection filters missing/deleted targets and deduplicates highlights without modifying
physical reference arrays. Existing live-concurrency reference tolerance stays intact;
the projected result satisfies P7-01's stricter portable schema. Tombstone commands remain
append-only; create/delete remain excluded from generic undo. No presentation viewport,
follow preference or presenter state is added to Y.Doc.

## Contracts used

Existing PresentationStep/maps/atomic arrays, shared UTF-16 text limits, integer order
within ±1,000,000, 50 live steps, 500 total unique highlights, finite world coordinates
within ±100,000 and positive rectangle dimensions at most 20,000. Existing command origins,
local UndoManager, physical validation and projection/remap ownership remain unchanged.

The contracts graph module exposes its existing field-only schema for partial/reorder
derivation: Zod 4.6.4 does not support pick/omit on refined schemas. Complete steps still
use the original combined-reference refinement. No dependency or lockfile change.

## Document and export evidence

Synthetic all-entity graph; four fixed seeds from `CONVERGENCE_SEEDS`. Each seed uses
two independent author documents with distinct client IDs and three fresh receivers,
duplicated/shuffled incremental updates, and converged graph comparisons. Local prefix/
remote suffix title edits and local suffix/remote prefix notes edits retain both authors'
inserts and original text; the same Y.Text object survives. Disjoint rect/highlight edits
survive together; competing reorder values converge without asserting author intent.
Concurrent step edit/delete retains the physical map and tombstone, hiding the step.
Receivers validate against the accepted initial document.

Pure checks cover one-update capture/reorder, deterministic ID ties, copied input geometry/
arrays, unknown and invalid input rollback, negative/world-limit geometry, notes/title/order
bounds, exactly 500 combined highlights and rejection of 501, 50-step cap and capacity
after tombstoning. Incremental text insertion above the notes limit rejects. Accepted step
map removal and tombstone clearing reject. Missing/wrong-kind/repeated/deleted node and
incident-edge highlights reject on commands and filter safely during projection.

Undo proof covers local text/rectangle/multi-step reorder with remote text/property survival,
redo and replica convergence; same-field remote rectangle/order winners survive local undo.
Notes/highlight undo with a remote title is included in the final focused check. Create/delete
exclusion and ID reuse/edit rejection prevent resurrection. No raster/JSON execution proof
is claimed; projection compatibility is a pure schema assertion.
